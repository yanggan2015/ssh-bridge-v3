# Web 可选 Token 认证（2026-11-24）

## 1. 目标

Web 控制台的写接口不再以“`web.token` 是否为空”判断只读，而是由独立开关 `web.require_token` 控制：

- **默认不使用 token**：新配置或 `web.token` 为空且未显式启用的配置，写接口直接开放。
- **启用 token**：写接口必须携带 `Authorization: Bearer <web.token>`；token 为空时不允许启用，写接口继续拒绝。
- 读接口始终公开，不受该开关影响。

这样既满足“默认不使用 token 即可写”的本地工作流，也保留需要时的 Bearer 保护。

## 2. 判定规则

| `require_token` | `web.token` | 写接口 | `/status` 展示 |
|---|---|---|---|
| `false` | 空 | 直接放行 | `token_required=false`、`token_set=false`、`readonly=false` |
| `false` | 已设置 | 直接放行（token 保留，便于以后启用） | `token_required=false`、`token_set=true`、`readonly=false` |
| `true` | 已设置 | 必须 Bearer 匹配 | `token_required=true`、`token_set=true`、`readonly=false` |
| `true` | 空 | 拒绝（配置异常态） | `token_required=true`、`token_set=false`、`readonly=true` |

兼容规则：配置 JSON 中没有 `require_token` 字段时，按 `!web.token.empty()` 取值。因此已有 token 的旧配置自动沿用“启用”，空 token 配置默认“不启用”。

`require_token` 总是随配置保存在 `web` 对象中；禁用 token 不清空 `web.token`，只是不再校验。

## 3. 配置与接口

```json
{
  "web": {
    "enable": true,
    "port": 18081,
    "require_token": false,
    "token": ""
  }
}
```

新增认证管理接口：

```http
GET /api/web/auth
→ {"ok":true,"enabled":false,"token_set":false}

POST /api/web/auth
{"enabled":true,"token":"tok-2026"}
→ {"ok":true,"enabled":true,"token_set":true}
```

- `POST` 本身受当前写保护约束。
- `enabled=true` 且最终 token 为空 → `400`，`error` 为“启用 token 前必须设置非空 token”。
- 保存成功后立即返回，再异步通知 UI 线程重启 Web 服务；配置文件和运行态保持一致，重启后仍生效。
- `enabled=false` 时保留已有 token。

`/status` 的 `web` 对象新增 `token_required`、`token_set`，`readonly` 改为 `require_token && token.empty()`。18096 UI 桥的 `/state.web` 同步这两个字段。

## 4. Web UI

仪表盘右上角原“令牌”按钮改为“安全”，面板内：

- `启用 token` 复选框，默认关闭；
- token 输入框；
- “保存设置”按钮，调用 `POST /api/web/auth`；
- 状态提示三态：`可写·未启用 token` / `可写·已带 token` / `需要 token`。

所有写操作统一走 `writeReady()`：未启用 token 直接允许；启用后浏览器必须已保存正确 token。上传、接管、通道、动作、继电器、服务、隧道等页面共用同一判定。

修复过一个交互 bug：用户输入 token 时 `setTok → syncTokenUI` 会把刚勾选的“启用 token”重置。增加 `AUTH_TOUCHED` 后，未保存的勾选不会被状态刷新覆盖。

配置页会显示 `require_token` 布尔标签；顶部的安全开关是主要入口。

## 5. Agent 帮助语义

`/api/help` 的 `auth` 与设备动作 `surfaces.device.auth` 按当前配置输出：

- 未启用：`open-write`，说明“未启用 Web token，写接口开放”；
- 启用：`bearer-write`，说明“写接口使用 Authorization: Bearer <web.token>”。

不再把空 token 一律描述为只读。

## 7. 边界与后续

- 旧配置中已有 token 且没有 `require_token` 时，默认继续启用；如果希望“已有 token 也默认关闭”，需要把兼容默认改为 `false`，并同步调整旧验收。
- 禁用 token 不删除 `web.token`；如需禁用即清空，另改认证接口。
- 启用但 token 为空会把配置置于只读异常态；正常 UI 流程已阻止该操作。需要手工修复配置文件。
- token 仍以明文保存在配置中，适用于本机/内网受控环境；更高安全要求应接入密钥存储或环境变量。
