## 0. 总则

### 0.1 目录与依赖方向

```
src/app/        装配层：app_main / app_core / lifecycle / selftest
src/core/       领域核心：config / logbuf / channel_core / cmd_queue / ssh / bridge(serial,ssh) / util
src/ui/         Win32 界面：shell / terminal / dialogs / sftp / services / tray / aibridge

```

`ui → core`、`services → core`，`app` 装配三者。`core` 不许 include `ui` 或 `services` 头文件。

### 0.2 核心对象

**LogBuffer（每通道一个）**——`v2: include\log_buffer.h`

| 字段 | 含义 |
|---|---|
| `buf / len / cap` | 环形存储、当前长度、容量（默认 1 MiB） |
| `total` | 自 clear 起累计写入的绝对字节数（单调递增） |
| `epoch` | clear 时自增；读者用它判断“世界重启过” |
| `notify_seq` | 提交可见字节后自增；读者先比它决定要不要读 |
| `cr_hold` | 块尾裸 `CR` 的暂存，避免半行卡住网页 |
| `ansi_state` | 0/ESC/CSI/OSC，行首时间戳要跨 ANSI 序列延后 |
| `disk / disk_dirty` | 落盘 FILE 与脏计数；flush 由后台线程做 |

接口（建议签名，与 v2 一致）：

```c
int  log_buffer_init(LogBuffer*, size_t cap, int timestamp,
                     int disk_enabled, const char *dir, const char *name);
void log_buffer_append(LogBuffer*, const void *data, size_t n);      /* RX 唯一入口 */
void log_buffer_ingest(LogBuffer*, const void *data, size_t n,
                       unsigned char **out, size_t *out_n);          /* 顺带拿副本给入站 */
char *log_buffer_get_since(LogBuffer*, uint64_t *epoch, uint64_t *seen, size_t *out_n);
void log_buffer_flush_cr_hold(LogBuffer*);
size_t log_buffer_clear(LogBuffer*);
uint64_t log_buffer_notify_seq(LogBuffer*);
int  log_buffer_set_disk(LogBuffer*, int enabled, const char *dir, const char *name);
```

写侧只有 RX 泵线程调用。读侧全部是无锁读：比 `notify_seq` → 取 `get_since` → 更新自己的 `epoch/seen`。

**ChannelCore（每通道一个）**——`v2: include\channel_core.h`

```c

void channel_core_on_rx(ChannelCore*, const unsigned char *data, size_t len);
```

### 0.3 线程模型

| 线程 | 数量 | 归属 | 允许做的事 | 禁止 |
|---|---|---|---|---|
| UI（主线程） | 1 | app | 建窗、消息循环、读 ring 渲染、开对话框 | 阻塞等待、sleep、直接写端口 |
| RX 泵 | 每通道 1 | core/bridge | 读设备/通道、append ring、kick | 碰 UI 对象、等读者 |
| writer | 每通道 1 | core/bridge | 消费 cmdq、写设备 | sleep 轮询以外的事、长阻塞 |
| HTTP poll | 1（S9/S10） | services/web | mongoose poll、WS 下行、Web/Agent 路由 | 任何 >2ms 控制面工作（交 JobRunner） |
| JobRunner | 1 队列 | services/web | 脚本、传输、慢 API、`command_block`/`exec` 等待、job 取消 | 直接写响应（要回 poll 线程） |
| 入站会话 | 每会话 1（S8） | services/inbound | 读客户端、写自己队列、读 ring | 为每个客户端新开 target ssh |
| 后台 flusher | 1 | core/logbuf | 每 250ms 刷盘 | 阻塞读路径 |

| `InboundSSHConfig` | `enable`、`port`（默认 2222） |

三级密码解析（入站用）：通道 `password` 有键（含显式 `""`）→ 用它；否则 → `default.password`；最终空串 = 免密（`none`）。

手术式热更新四步：读新 JSON → 算 diff（新增/删除/改名/改参数）→ 只重建受影响通道（其它 ring 与游标不动）→ 用 `http_manager_set_bridges` 原子换列表（S9 起）。

### 0.5 状态与错误

- 所有 `get_status_json()` 统一字段：`name / type / running / port / buffer / total / log_enabled / last_error`。
- 错误只走返回值 + `last_error` 字符串，热路径不 `assert`、不 `fprintf`。
- 崩溃写 `work/logs/crash.txt`：版本、最后 200 行 ring、线程号。

接口（实际落地的 C++ 形状，替代旧稿的 C 函数列表）：

```cpp
// config
bool config_load(const std::string& path, AppConfig* out);
```

行为要点：

1. 串口按 `baudrate/databits/parity/stopbits/flowcontrol/dtr/rts` 组 DCB；`stopbits_x10` 用 10/15/20 存。
2. 读循环：`WaitCommEvent(EV_RXCHAR)` + overlapped `ReadFile`，超时 150ms 时调 `flush_cr_hold()`。
3. 只有 RX 泵线程 append ring；append 后 `notify_seq++` + `kick`。
4. 下行：`write` 入 `CmdQueue`（mutex + cv + deque），writer 线程按 `line_ending/encoding` 加工后写；`stop()` 关队列、`start()` 必须 `reset()` 重开。
5. 落盘：读线程只写 ring 与 `fwrite` 缓冲，后台每 250ms `fflush`。
6. 时间戳只在上行、写 ring 之前打，且跨 ANSI CSI/OSC 延后到行首。
7. `timestamp` / `buffer_size` 变化走重建 ring（`clear()` 即 `total=0 + epoch++`，旧游标自动被夹到 `total`）。
8. `serial_device` 以 `loop:` 开头时走内置回环端点：writer 把加工后的字节推进 `loop_in_`，RX 泵每 150ms 取批量送 `on_rx`。用于无回环硬件时跑完整链路（D11）。
9. 端口被占用时 `last_error` 必须含 `busy` 语义，不能只返回 false。

明确不做：任何窗口、任何端口、SSH、入站。

自检与闸门：

- `--selftest ring` / `config` / `serial <A> <B|loop:x>` / `all [A] [B|loop:x]`；结果写 `output\selftest\result.txt`，GUI 子系统无 stdout。
- `tests\step1_check.ps1`（`-SkipBuild` 可跳过编译）逐条解析 PASS 行，另含退出码、单实例、无监听、无残留、`quality_gate`、git 状态。

验收（T1）：T1-1 配置往返一致 · T1-2 1 MiB 无丢字节 · T1-3 半满/回绕后 `read_since` 连续 · T1-4 clear 后 epoch 变化且游标被夹紧 · T1-5 串口回环收发一致（无硬件时以 `loop:` 端点判定）· T1-6 落盘与 ring 逐行一致 · T1-7 端口被占用时错误明确 · T1-8 退出无残留线程。

## 3. S2 SSH 出站链路

> 状态：**已实现并验收**（T2 六项 + G 五项全 PASS，提交见 `docs\执行记录.md §5`）。

| 模块 | 路径 | 职责 |
|---|---|---|
| ssh_session | `src/core/ssh/` | libssh 会话/通道封装：建链、认证、PTY、非阻塞读、阻塞写、保活 |
| ssh_bridge | `src/core/bridge/ssh/` | 实现同一 `IBridge` 契约、重连退避、状态上报 |
| cmd_queue | `src/core/cmd_queue.h/.cpp` | 下行队列（从 serial_bridge 抽出，串口与 SSH 共用） |

接口（实际落地）：

```cpp
struct SshTarget { host; port; username; password; term; width; height;
                   connect_timeout_ms; keepalive_s; };

class SshSession {                 // 一个会话只服务一条通道；内部 mutex 串行化
    bool connect(const SshTarget& t);
    void close();
    bool connected() const;
    int  read_some(void* buf, size_t cap);     // >0 字节；0 暂无；-1 断开
    bool write_all(const void* data, size_t n);
    bool keepalive();                          // ssh_send_ignore
};

class SshBridge : public IBridge {
    bool start(); void stop(); bool running() const;  // running == 已连上
    void reconnect();
    bool wait_connected(unsigned ms); bool wait_disconnected(unsigned ms);
    std::string status_json();                        // state/peer/last_error/reconnects/…
};
```

行为要点：

1. 连接参数走 `ssh[]` 段：`target_host/target_port/target_username/target_password`、`term/width/height`、`connect_timeout_ms`（旧名 `connect_timeout` 兼容）、`keepalive`（秒，0=关）。
2. 认证：密码优先；密码为空或密码失败后再试 `none`（板子常配免密）。
3. `PTY(term,width,height)` → `shell`，成功后 `state=ready`、`running=true`；失败只写 `last_error`，对象仍存在（首连失败不阻塞启动）。
4. RX：`ssh_channel_read_nonblocking` 循环 → `core_.on_rx`（与串口同一路径：只有 RX 线程写 ring）。
5. TX：`write` 只入 `CmdQueue`；TX 线程按 ≤1024 字节分块 `ssh_channel_write`；断线期间丢弃，不补发陈旧命令。
6. 保活：空闲满 `keepalive` 秒发一次 `ssh_send_ignore`；失败即判断开。
7. 断线：指数退避 1s→2s→4s→…（上限 30s），只影响本通道；`reconnect()` 可立刻打断退避重试。
8. `status_json`：`name/type=ssh/running/state/peer/last_error/reconnects/rx_bytes/tx_bytes/queue/buffer/log_enabled`。
9. 链接方式：`-DLIBSSH_STATIC` + `$(MINGW)/lib/libssh.a` 全静态链接，产物只依赖系统 DLL。

明确不做：入站（S8）、SFTP（S7）、本地回显。

自检与闸门：

- `--selftest ssh <host> <port> <user> <pass>`、`ssh-auth`、`ssh-drop`、`ssh-reconnect`、`ssh-two <host> <p1> <p2> <user> <pass>`。
- `tests\step2_check.ps1` 自带 paramiko 测试服务器（`tests\tools\ssh_test_server.py`），负责起服务、杀服务（拔网）、同端口重启（恢复），逐条解析 PASS 行。

验收（T2）：T2-1 连接成功且拿到 shell · T2-2 发命令回显顺序正确 · T2-3 拔网 5s 内标记断开 · T2-4 自动重连成功 · T2-5 两条链路互不影响 · T2-6 密码错误给出可读错误。

6. 回看容量按行数（默认 5000 行，可配）；选中复制、右键粘贴；粘贴按原样写入 cmdq（`line_ending` 只作用于命令行接口，不作用于粘贴）。

8. “加载历史会话”（右键）：把该通道 ring 全量重放进窗格（不改服务端、不清别人）。
9. 字体：Ctrl+滚轮缩放；字号进 `ui_prefs.ini`。

  - 桌面 `WM_CHAR` 逐字 `send_active()`，网页对应 xterm `onData`，每键进入 8ms 合批队列后立即 `/write`，`IN_CHAIN` 串行保证多键顺序；

## 11. S10 Agent 双面接口（18081 设备控制 / 18096 UI 调试）

> 设计初衷：**让 AI Agent 友好、完整地控制板子，同时给人一套友好的界面**。
> 18081 是唯一板控主路径，必须独立完成全部控板能力；18096 只用于桌面窗口调试/人工兜底（**不为板控兜底**），不参与板控闭环，18081 不得反向依赖 18096。
> 完整执行批次与验收映射见 `docs/AGENT-EXECUTION-LIST.md`。

### 11.0 硬边界

| 项 | 18081 设备控制面 | 18096 桌面 UI 桥 |

| 使用者 | Agent、CLI、脚本、Web 前端 | 调试脚本、UI 回归、人工兜底 |
| 数据源 | `ChannelCore`、`LogBuffer`、`ServiceManager` | `bridge_host` + Win32 控件树 |
| 是否主路径 | **是**。所有板控能力必须在这里闭环 | 否。只覆盖“尚未建模成设备 API 的窗口操作” |
| 独立验收 | 关闭 18096 后，T10-1 全部通过 | 关闭 18081 后，T10-2 全部通过 |

### 11.2 通道选择规则（所有板控请求统一）

`board`、`link`、`channel` 三选一，语义固定：

| 键 | 只允许 | 说明 |
|---|---|---|
| `board` | 串口通道 | 传统板名，等价于 kind=serial |
| `link` | SSH 出站 Link | 远端主机链路，等价于 kind=ssh |
| `channel` | 任意通道 | 新代码推荐；必须能在当前通道表唯一命中 |

归一化顺序：解析一个键 → 查注册表 → 校验 kind。`board/link/channel` **必须且只能出现一个**；出现两个及以上，即使指向同一通道也返回 400 `channel_conflict`。无键 400 `channel_required`；不存在 404 `channel_not_found`；`board` 命中 SSH 或 `link` 命中串口，400 `channel_kind_mismatch`。

`GET /api/agent/resolve` 对已配置但未运行的通道返回 `200 + running:false`，便于 Agent 先发现再决定是否启动；真正下发动作的 `/command*` 对未运行通道返回 409 `channel_down`（`/log` 仍可读）。

所有响应必须回显 `channel` 与 `kind`，便于 Agent 确认没有操作错板。

### 11.4 上下文与终端态

| 接口 | 返回 | 说明 |
|---|---|---|
| `GET /status?view=agent` | 精简通道表 + 服务状态 + 锁摘要 | 不返回 UI 控件树；适合每次循环前置 |
| `GET /agent/scan` | 全通道上下文 | 连接态、终端态、缓冲区、按钮、features、错误 |
| `GET /agent/probe?board=&link=&channel=&tail=` | 单通道探测 | **纯被动**，只读日志尾部，不发 Enter、不发字节 |
| `GET /agent/state?board=&link=&channel=` | 单通道业务状态 | 连接、终端态、日志游标、锁、最近动作、错误 |
| `GET /actions?channel=&view=agent` | 可用按钮 | `id/label/backend/enabled/kind/requires_lock` |

`/agent/probe` 状态机：

```text
disconnected → login → password → uboot / shell / unknown
```

判定优先级：连接未运行 = `disconnected`；日志尾部命中 `login:` = `login`；命中 `Password:` = `password`；命中 `U-Boot>` / `=>` / `Hit any key` = `uboot`；命中 `$` / `#` / `root@` = `shell`；否则 `unknown`。`confidence` 取 `high|medium|low`，无法判定必须返回 `unknown`，不得猜 `shell`。

`/agent/probe` 与 `/agent/scan` 是只读接口，不改变设备状态；Agent 若要用 Enter 唤醒，必须显式调用 `/send_keys`，不能藏在 probe 里。

### 11.5 日志与增量游标

`GET /log` 统一支持：

```text
/log?channel=&chars=65536
/log?channel=&since=123&epoch=7&chars=65536
```

- 无 `since`：返回末尾 `chars` 字节，兼容现有 Web 终端。
- 有 `since`：调用 `LogBuffer::read_since(epoch, since, ...)`，只返回新字节；`dropped` 时返回 `dropped_bytes`。
- `epoch` 不匹配：返回 `reset:true` 和当前尾部，Agent 必须丢弃旧游标。
- 响应头：`X-Log-Epoch`、`X-Log-Total`、`X-Log-Dropped`；JSON 同时带同名字段。
- `/log`、`/log/download`、`/log/clear` 保留；新增 `POST /log/disk` 开关落盘，不影响读取。

**C3 实现口径（2026-11-23）**

- 代码：`web_console.cpp` 的 `/log`、`/log/clear`、`/log/disk`；`logbuf.cpp` 的 256MB 上限；`IBridge` 增加 `read_since_ex`、`log_epoch/total/capacity`、`disk_log_enabled/error`。
- 响应 JSON 固定：`ok/channel/mode/text/chars/epoch/total/next_since/dropped/dropped_bytes/reset/truncated`；增量时加 `since`，reset 时加 `reset_reason`。
- `mode=tail`：无 `since`，返回最后 `chars` 字节，`next_since=total`；读取尾部不移动服务端游标。
- `mode=incremental`：`since` 与 `epoch` 必须同时给出且均为无符号十进制；缺 `epoch`、负数、非数字、溢出均为 `400 invalid_cursor`。`since` 越过总游标返回 `reset:true, reset_reason=cursor_ahead`；epoch 不匹配返回 `reset:true, reset_reason=epoch_mismatch`，两者都带当前尾部。
- `chars`：尾部默认 8192、增量默认 65536，均 clamp 1–65536。增量超过 `chars` 时按“最旧未读字节优先”截断，`truncated:true`，`next_since` 只推进到已返回字节，Agent 可连续分页补齐，不跳字节。
- `dropped`：ring 已覆盖游标时返回 `true`，`dropped_bytes` 是已丢失的起始字节数；文本从 ring 最旧可读字节开始。
- `/log/clear`：`LogBuffer::clear` 递增 epoch、total 归零；响应额外带新 `epoch/total`；所有读者下一次带旧 epoch 请求都会收到 `reset:true`。
- `/log/disk`：`POST {channel,enabled}`（兼容 query `enabled`），仅运行时开关，不写配置文件；状态以 `LogBuffer::disk_enabled()` 为准，SSH 通道也改为读实际值。成功返回 `ok/channel/enabled/disk_enabled`；打开失败返回 `500 {error:"log_disk_open_failed",message}`。
- 落盘上限：单文件 256MB。打开时已达上限则拒绝；写入将越界时停止落盘、置 `last_error` 并关闭文件，后续读取不受影响。
- 只读：`/log` 只读 ring，不写 cmdq、不发 Enter；`/log/disk` 只动日志文件，不碰通道数据面。


### 11.6 动作语义

| 接口 | 时序 | 参数 | 结果 |
|---|---|---|---|
| `POST /command` | 立即受理 | `channel, command, line_ending?` | `202 {ok, job_id, queued:true}` |
| `POST /command_block` | 有界等待 | `channel, command, timeout_ms?`（默认 2000，最大 60000） | `{ok, output, timed_out, elapsed_ms}` |
| `POST /agent/exec` | 标记等待 | `channel, command, timeout_ms?`（默认 10000，最大 60000） | `{ok, output, marker, timed_out, elapsed_ms}` |
| `POST /write` | 立即受理 | `channel, data` 或兼容 `text` | `202 {ok, bytes, request_id}` |
| `POST /send_keys` | 立即受理 | `channel, keys[], interval_ms?` | `202 {ok, count, job_id}` |
| `POST /action` | 立即受理/短任务 | `channel, id, backend?, session?` | `202 {ok, job, job_id, queued}` |

时序约束：

1. `/command` 只负责入队，不返回命令输出；Agent 必须再用 `/log`、`/agent/probe` 或 `/agent/exec` 验证。
2. `/command_block` 与 `/agent/exec` 的等待发生在 JobRunner 中，HTTP 连接挂起由 wakeup 回写；**poll 线程不 sleep**。
3. `/agent/exec` 只在 `terminal=shell` 时使用；发送前 probe，probe 不是 shell 返回 409 `state_mismatch`。
4. `/send_keys` 的 `keys` 是字符串数组；`\r`、`\u0003`、`\u0004` 按字面转义，`interval_ms` 限制 10–1000。
5. `/action` 必须复用 `/actions` 返回的 id；不存在 404，disabled 409，后端不支持的 backend 400。
6. 所有写接口统一先 `reject_if_locked()`，再 `channel_down` 检查，再入队；顺序不可颠倒，否则会向已断通道写数据。

**C4 实现口径（2026-11-23）**

- 统一作业模型：`TaskKind={Action,Command,CommandBlock,Exec,SendKeys}`，`Task` 携带 channel、命令、行结束符、按键、超时和 bridge；`Job` 固定 `id/kind/channel/state/done/ok/timed_out/marker/message/output/error/request_id/session/action_id/时间戳/timeout_ms/bytes`。状态为 `queued/running/done/failed/timeout`。
- 单 worker 串行执行，队列上限 64；队列满返回 429 `queue_full`，并删除未入队的 job。Job 只保留结构化摘要与输出，**不保存原始命令/密码全文**。
- `/write` 改为 `202 {ok,bytes,request_id}`；body 接受 `data` 或 `text`，原样写入不追加行结束符；通道未运行返回 409 `channel_down`。
- `/command` 返回 `202 {ok,job_id,queued:true}`；默认追加 CR，`line_ending` 支持 `none/cr/lf/crlf` 及字面 `\\r/\\n`；worker 只写通道后立即 done，不等待回显。
- `/command_block` 先写 `command+line_ending`，再增量读 ring；首包后 150ms 无新字节视为完成；超时置 `timed_out:true,state=timeout`；默认 2000ms，最大 60000ms。HTTP 请求由 JobRunner 登记挂起，worker 完成后 `mg_wakeup` 把 job id 发给 poll 线程，`MG_EV_WAKEUP` 解析后回写 200，poll 线程不 sleep。
- `/agent/exec` 前置用 `agent::probe_json` 判定终端；非 `shell` 返回 409 `state_mismatch`，并带实际 `terminal`。worker 发送 `command+line_ending` 与 `echo __C4_END_<jobid>__`，读到 marker 后截到 marker 所在行之前；默认 10000ms，最大 60000ms。
- `/send_keys` 用 `normalize_key_char` 归一每个字符串（支持 `<Ctrl+C>`、`\u0003`、字面 `\\u0003`），最多 256 键；interval 默认 50、范围 10–1000；返回 `202 {ok,count,job_id}`。
- `/action` 响应保留旧 `job` 字段并新增 `job_id/queued`；先查 `/actions` id，未知 404 `action_not_found`、disabled 409 `action_disabled`、`backend` 与配置不符 400 `backend_mismatch`、通道未运行 409 `channel_down`。
- 审计：`job_object.audit` 固定 `request_id/session/channel/action/status/duration_ms/bytes`；`X-Request-Id` 原样回传，`X-Agent-Session` 或 body `session` 记录会话。`/job?id=` 可直接查。
- 锁：C4 不实现锁拒绝，也不伪造 423；所有写接口已按“鉴权→通道存在/运行→入队”顺序预留，租约锁在 C5 统一插入该顺序的最前面。

### 11.7 租约锁

| 接口 | 请求 | 说明 |
|---|---|---|
| `POST /lock` | `{channel, session_id?, ttl_ms?}` | 默认 1000ms，范围 100–86400000ms；同 session 续租 |
| `POST /unlock` | `{channel, session_id?}` | 只有持有者可解；错误 session 不释放 |
| `GET /agent/state` | — | 返回 `lock{owner,expires_in_ms}` |
| `POST /lock/takeover` | `{channel, reason}` + 人类 token | 人工显式接管，先释放旧锁并记 audit |

- session 从 `X-Agent-Session` 头取；没有则用 body `session_id`；都没有 400。
- 被他人锁：423 `agent_lock`，响应带 `owner`、`expires_in_ms`、`can_takeover`。
- 锁按 **channel** 隔离，不是全局锁。
- 读接口不受锁影响；`/write`、`/command*`、`/send_keys`、`/action`、串口关闭/重配受锁约束。
- 本地桌面键盘始终优先；人工在 UI 输入视为接管信号，清除该通道的 Agent 锁并记 audit（防止 Agent 崩溃后把人锁死）。Web 人工终端同理，必须显式点“接管”，不能静默绕过。

**C5 实现口径（2026-11-23）**

- 锁表独立为 `src/services/agent/agent_lock.{h,cpp}`，进程内单例 `lease_locks()`；按 channel 保存 `LeaseInfo{active,channel,owner,session,ttl_ms,acquired_ms,expires_ms,remaining_ms,last_takeover_*}`。锁只在进程内生效，不落盘，进程退出即释放。
- TTL 惰性清理：每次 `check/acquire/release/takeover/get/list` 都先把已过期的 active 置 false，保留 `last_takeover` 审计；过期后下一个 session 可直接获取。
- `POST /lock` 要求 `Authorization: Bearer <token>`；`session_id` 优先取 body，其次 `X-Agent-Session`，都没有返回 400 `session_required`；`ttl_ms` 默认 1000、范围 100–86400000，越界 400 `invalid_ttl`。同 session 再次 `POST /lock` 视为续租，返回 `renewed:true`，`ttl_ms/expires_in_ms` 按本次参数重置；不同 session 返回 423 `agent_lock`，带 `owner/expires_in_ms/can_takeover:true`。
- `POST /unlock` 只有持有者可解；无锁返回 `200 {ok:true,released:false}`，错误 session 返回 423 `agent_lock` 且不释放；缺 session 400。
- `POST /lock/takeover` 要求 token，`reason` 必填，缺 reason 400；成功返回 `{ok,channel,previous_owner,reason,at_ms}`，无锁也返回 200 且 `previous_owner` 为空；旧锁存在时记录 `last_takeover{reason,actor,previous_owner,at_ms}`，`actor` 取 `session_id` 或 `"human"`。
- 写路由统一经过 `allow_channel_write()`：`/write`、`/command`、`/command_block`、`/agent/exec`、`/send_keys`、`/action`。顺序固定为 **鉴权 → 通道存在 → 锁校验 → 通道 running → 入队**；被他人锁返回 423，不写通道、不建 job。`/lock`、`/unlock`、`/lock/takeover` 自身不受锁校验；`/log`、`/agent/state`、`/status`、`/agent/scan`、`/agent/probe`、`/actions` 等读接口不受锁影响。
- 状态与发现：`features.lock=true`；`/agent/state.lock` 返回 `{enforced:true,held,owner,ttl_ms,expires_in_ms,can_takeover,last_takeover}`；`/agent/scan` 与 `/status?view=agent` 的 `locks` 返回 `{enforced:true,note:"per-channel lease lock",leases:[{channel,owner,ttl_ms,expires_in_ms}]}`；`/actions?view=agent` 与 `channel_json` 的 `requires_lock/lock_enforced` 均为 true。
- `/api/help` operations 由 54 增至 57，新增 `lock.post`、`unlock.post`、`lock.takeover.post`。
- 本地人工接管：`src/ui/terminal/view.cpp` 把 `send_active()` 拆为 `send_active()`（human=true）与 `send_bytes(bytes, human)`；WM_CHAR/WM_KEYDOWN、粘贴先调用 `human_input(channel,"local-keyboard")`，鼠标上报调用 `human_input(channel,"local-mouse")`，仅在该通道有活动锁时清锁并记 `actor="local-human"`。18096 UI 桥的 `type_text/send_raw` 走 `send_bytes(...,false)`，不会静默清锁。

### 11.13 安全与审计

1. 18081 写接口必须 token；读接口默认只读，可通过 `api_read_token` 收紧。
2. 不返回密码、token、配置密钥；帮助和日志中的密码字段脱敏。
3. Tunnel 启停、任意 host shell、服务关闭不进入 Agent help；只能人工或显式管理接口。
4. 每个 Agent 写动作记 audit：`request_id/session/channel/action/status/duration/bytes`，不记原始命令全文。
5. `/api/config` 的明文只对 token 持有者；Agent 帮助不暴露。
6. 请求体 16MB 上限；上传分片；长命令限制长度 4KB。

## 12. S11 继电器 / TFTP / NFS / 共享目录

### 12.1 继电器

| 模块 | 路径 | 职责 |
|---|---|---|
| relay_ctrl | `src/services/relay/relay_ctrl.*` | 按 A0 协议开串口、置位/脉冲、关闭 |
| relay_panel | `src/ui/relay/` | 设备列表、每路状态、点击切换 |
| buttons hook | `src/ui/quick_buttons/` | `backend=relay`：`hold_on/hold_off/pulse` |

要点：

1. 每次操作“开串口 → 写 A0 → 关串口”，不常驻占用继电器串口；`post_write_delay_ms` 默认 100ms。
2. 三种模式：`hold_on`、`hold_off`、`pulse`（`hold_seconds` 到点自动回 idle；极性由 `polarity_inverted` 决定）。
3. 设备字段：`enable / windows_port / relay_channels(2) / baudrate(9600) / io_inverted / post_write_delay_ms`。
4. 互斥：某通道某 id 已用 `commands` 且 enable 时，再 enable `relay` 返回 409。
5. 脉冲期间 `/status` 不得冻结（继电器操作在独立线程/短任务，不占 poll）。

### 12.2 TFTP

`v2: include\tftp_svc.h`

```c
int  tftp_svc_start(TftpSvc*, const char *root, int port, int allow_write, char *err, size_t);
void tftp_svc_ensure_layout(const char *root, const char **names, int n);
```

要点：UDP 69（Windows 可能需管理员/换端口）；`root` 缺省 `{work}/share`；`ensure_layout` 建 `common/` 与每板目录；RFC2347 协商 `blksize`，超过 `blksize×65535` 回 ERROR 而不是截断。

### 12.3 NFS 与共享目录

- NFS：内嵌 `winnfsd` 子进程导出同一 `share` 根，`export_alias` 默认 `/share`；只提供开启，不提供“关闭导出”语义（板端只 mount 不 umount）。
- 共享：同目录 HTTP 浏览/上传/下载/删除/建目录；与 TFTP/NFS 共用一份文件，避免“三份副本对不上”。

## 13. S12 TCP 转发 / 隧道 / 发现

| 模块 | 路径 | 职责 |
|---|---|---|
| tcpfwd | `src/services/tcpfwd/` | 按板 IP 末字节映射本地端口 → 板 :22 |

5. 发现：只对 `enable && discoverable` 的通道应答，内容含通道名、主机、端口；默认不应答。
6. 转发能力提示：Agent 优先用系统 `ssh -L`，无该能力时才用本功能。
