# 板卡按钮脚本参考（S12 / v3）

适用：SSH Bridge 3.0 `backend=script` 按钮。入口是主窗口「板控按钮」或继电器窗口「按钮脚本」页。

## 1. 两种脚本引擎

| 首行非空内容 | 引擎 | 能力 |
| --- | --- | --- |
| `--lua` 或 `#!lua` | Lua 5.4 | 变量、if/while、读回显后分支、重试 |
| 其它 | 简单脚本（行式 DSL） | 顺序执行、无分支；兼容 v2 写法并做了增强 |

- 「类型」下拉选「Lua 脚本」保存时，如果没有 `--lua` 首行会自动补上。
- 选「简单脚本」保存时，如果首行是 `--lua` 会拒绝，避免两种引擎混用。
- 整段脚本总时限约 180 秒；`send_keys` 单次最长 120 秒；`msleep` 单次最长 120 秒。
- 按钮触发和脚本每一行 `print/echo/hostcmd/remotecmd` 输出都会实时显示到主窗口状态栏，详见第 5 节。

## 2. Lua API

### 通道

| 调用 | 说明 |
| --- | --- |
| `channel.mark()` | 记录当前串口/SSH 日志游标，后续读取只取这之后的内容 |
| `channel.write(s)` | 原样写入字符串；换行要自己写 `\r\n` |
| `channel.send("<enter>")` | 发送单个按键或字符，支持 `<ctrl+c>`、`<space>`、`<tab>` 等 |
| `channel.keys(" <ctrl+c>ab")` | 按键序列各发一次 |
| `channel.send_keys(seq, duration?, interval?)` | 轮询连发；默认 7 秒 / 0.1 秒，返回发送次数 |
| `channel.login()` | 用通道配置的用户名/密码登录（固定 `\r\n`） |
| `channel.read_since(mark)` | 读 mark 之后的全部文本（不是增量） |
| `channel.wait_mark(mark, needle, timeout)` | 等文本包含 needle；成功返回文本，超时返回 `nil, "timeout"` |
| `channel.wait` / `channel.expect` | `wait_mark` 的别名 |
| `channel.wait_idle(mark, idle_ms, timeout)` | 收到数据后空闲 idle_ms 视为结束；超时返回 `nil, "timeout"` |
| `channel.exec(cmd, timeout?)` | 发命令并等回显空闲，等价于 `remotecmd` |

### 继电器与板卡按钮

| 调用 | 说明 |
| --- | --- |
| `relay("NAME", ch, "on"\|"off")` | 直接吸合/释放，对应 hold_on/hold_off |
| `relay_mode("NAME", ch, "hold_on"\|"hold_off"\|"pulse", hold?, polarity?)` | 支持脉冲；`hold` 秒，`polarity=true` 反转脉冲电平 |
| `action("ID")` | 执行同通道已有按钮（relay / commands / script）；嵌套深度上限 6 |
| `board.action("ID")` | 同 `action` |
| `board.power_on()` / `board.power_off()` / `board.reboot()` | 调用同通道的 `power_on` / `power_off` / `reboot` 按钮 |

### 本机命令

| 调用 | 说明 |
| --- | --- |
| `host_exec(cmd, timeout_ms?)` | 本机执行命令，返回 `{ok, exit_code, output}` |
| `hostcmd(cmd, timeout_ms?)` | `host_exec` 的别名 |
| `host.exec(cmd, timeout_ms?)` | 同上，表写法 |

本机命令通过 `cmd.exe /c` 执行，工作目录是配置里的 `project_root`（为空时用程序运行目录）。返回的 `output` 同时包含 stdout 和 stderr，并逐行送到状态栏。

### 其它

| 调用 | 说明 |
| --- | --- |
| `msleep(ms)` | 毫秒睡眠，单次最多 120000 |
| `sleep(seconds)` | 秒睡眠，单次最多 120 |
| `print(...)` | 输出到按钮执行结果和 `board_action.log` |
| `error(msg)` | 立即失败并中止脚本 |

沙箱：没有 `io` / `os` / `package`，不能读写本地文件；本机操作统一走 `hostcmd`。

## 3. 简单脚本（行式 DSL）

一行一条，`#` 开头为注释，空行忽略。除 v2 原有的 `write/send/keys/send_keys/login/relay/msleep/action` 外，v3 新增：

| 指令 | 说明 |
| --- | --- |
| `relay NAME ch N on\|off\|pulse [秒]` | 新增 `pulse`；`on/off` 与 v2 一致 |
| `hostcmd CMD [timeout=秒]` | 本机命令，默认 120 秒 |
| `host` | `hostcmd` 别名 |
| `remotecmd CMD [timeout=秒]` | 板端命令，默认 10 秒 |
| `cmd` | `remotecmd` 别名 |
| `expect TEXT [timeout=秒]` | 等到回显包含 TEXT，默认 10 秒；超时算失败 |
| `assert` | `expect` 别名 |
| `echo TEXT` | 输出一行，支持 `${USER}` `${PASS}` `${CHANNEL}` |
| `print` | `echo` 别名 |
| `login [USER PASS]` | 不填参数时用通道配置；填了则用指定账号 |
| `sleep MS` | `msleep` 别名 |

`write` 支持 `\n` `\r` `\t` `\\` `\xNN` 转义；`send_keys` 支持 `duration=秒`、`interval=秒`。

> `action` 可以调用同通道的 `relay/commands/script` 按钮，嵌套深度上限 6；不要写互相调用的环，否则会在深度上限处失败。

## 4. OK3568 示例（COM5 + COM4 单路继电器）

继电器 `relay1`：`COM4`，1 路，`CH1` 接板子电源。`hold_on` = 上电，`hold_off` = 下电。

### 4.1 进 U-Boot

```lua
--lua
local RELAY = 'relay1'
local CH = 1
relay_mode(RELAY, CH, 'hold_off', 0)
sleep(1.2)
local mark = channel.mark()
relay_mode(RELAY, CH, 'hold_on', 0)
local out = ''
local hit = false
for i = 1, 360 do
  channel.send('<ctrl+c>')
  channel.send('<space>')
  local d = channel.read_since(mark)
  if d and #d > 0 then out = d end
  local lo = string.lower(out)
  if string.find(lo, 'u-boot', 1, true) or string.find(out, '=>', 1, true) then
    hit = true
    break
  end
  msleep(40)
end
if #out > 0 then print(out) end
if hit then print('UBOOT: entered') else print('UBOOT: no U-Boot prompt seen') end
```

### 4.2 自动登录

```lua
--lua
local RELAY = 'relay1'
local CH = 1
local USER = 'root'
local PASS = 'YOUR_PASSWORD'

relay_mode(RELAY, CH, 'hold_off', 0)
sleep(1.2)
local m = channel.mark()
relay_mode(RELAY, CH, 'hold_on', 0)

local text = channel.wait_mark(m, 'login:', 30)
if not text then error('30 秒内没有出现 login:') end
channel.write(USER .. '\r\n')

local mp = channel.mark()
if not channel.wait_mark(mp, 'assword:', 12) then
  error('输入 root 后没有出现 password:')
end
channel.write(PASS .. '\r\n')

local m1 = channel.mark()
local out = channel.wait_idle(m1, 350, 8) or ''
print(out)
local low = out:lower()
if low:find('incorrect') or low:find('denied') or low:find('failure') then
  local m2 = channel.mark()
  if not channel.wait_mark(m2, 'assword:', 6) then
    error('重试前没有再次出现 password:')
  end
  channel.write(PASS .. '\r\n')
  print(channel.wait_idle(channel.mark(), 350, 8) or '')
end
```

### 4.3 上电 / 下电 / 重启

- `power_on`：继电器 `hold_on`
- `power_off`：继电器 `hold_off`
- `reboot`：Lua 脚本，`hold_off` 1.2 秒后 `hold_on`

单路继电器只控制电源时，不要用 `pulse` 当重启；`pulse` 只适合“按一下再松开”的按键型接线。

### 4.4 本机命令 + 板端命令 + 继电器组合

简单脚本示例（适合做上电后自检）：

```text
echo "BOARD: ${CHANNEL} start"
hostcmd echo HOST_OK
remotecmd uname -a timeout=5
relay relay1 1 on
msleep 500
echo "BOARD: done"
```

Lua 示例（按本机命令退出码决定是否继续）：

```lua
--lua
local hr = host_exec("ping -n 1 127.0.0.1", 8000)
print("host ok=" .. tostring(hr.ok) .. " exit=" .. tostring(hr.exit_code))
if not hr.ok or hr.exit_code ~= 0 then error("本机预检失败") end
relay_mode("relay1", 1, "hold_on", 0)
print("RELAY: on")
```

同通道内可以直接调用已有按钮，不需要重复写脚本：

```lua
--lua
action("power_off")
sleep(1.2)
action("power_on")
print("POWER: cycle done")
```

## 5. 状态栏实时反馈

主窗口状态栏分 4 段：左侧概览、当前通道、**触发的按钮 ID / 执行状态**、**脚本当前输出行**。分屏时第 2 段显示 `当前：画框N · 通道名`，空画框显示 `当前：画框N · 空`；按钮条同步跟随激活画框，并在左侧标注 `板控 · 画框N · 通道名（无按钮）`。

- 点击任意板控按钮后，第三段立即显示 `按钮：<ID>  执行中 N.Ns`，结束后变成 `✓ 按钮：<ID>` 或 `⚠ 按钮：<ID>`。
- 脚本中的 `print` / `echo`，以及 `hostcmd` / `remotecmd` 的回显，每产生一行就刷新第四段 `输出：<当前行>`。
- 执行结束后，第四段保留脚本最后一行，方便回看；没有输出的按钮则显示上一条操作提示。
- 第四段约占状态栏一半宽度，长输出会按状态栏宽度截断，但脚本原始输出仍完整保存在 `output\board_action.log`。

### 5.1 分屏布局持久化

分屏数量、每个画框绑定的通道和激活画框会自动写入配置的 `ui` 段；重启程序后按原样恢复，失效通道会被清空为空画框。示例：

```json
"ui": {
  "split": 4,
  "active_pane": 0,
  "pane_channels": ["ok3568", "loop1", "s6loop2", ""]
}
```

- `split` 只能是 1 / 2 / 4。
- `pane_channels` 与画框一一对应，空串表示空画框。
- `active_pane` 是重启后获得焦点的画框序号，从 0 开始。
- 切换画框、给画框选通道、切换分屏时会立即保存，不需要手动保存配置。

## 6. 执行与排错

1. 脚本页选目标通道，选中按钮，点「测试执行」。
2. 结果看 `output\board_action.log`，失败会带 Lua 行号和中文原因。
3. `ok:true` 只代表按钮动作已送达，真实结果以 `board_action.log` / `/state` 为准。
4. 串口没有任何回显时，先确认波特率、DTR/RTS、TX/RX 接线和继电器是否真的控制板子电源，再怀疑脚本。
