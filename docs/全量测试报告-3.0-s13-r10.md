## 三、本轮发现并修复的真实缺陷

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | `file_browser.cpp` 未实现文档声明的隐藏/系统属性过滤、14 类噪声后缀过滤、500 项上限 | 文件页展示噪声文件、超大目录卡顿 | 补齐过滤与 500 项截断，显示“已截断” |
| 2 | 文件页路径标签被 `SS_ENDELLIPSIS/SS_PATHELLIPSIS` 截断 | 路径不可读 | 改为相对 `project_root` 显示，桥接文本同步 |
| 3 | `shell.cpp` 板控 scope 固定 190px，split4 标题被截断 | 分屏板控归属不可读 | 按文本实测宽度动态分配，上限为可用宽度 1/2 |
| 4 | `share_server.cpp` 直接打印 `fs::last_write_time` 负数 epoch | HTTP 文件列表时间错误 | 转 `time_t` 后本地格式化 `YYYY-MM-DD HH:MM` |
| 5 | 窄窗状态栏固定 22/50/70% 分段互相挤压，长输出硬切 | 状态栏黏连、不可读 | 新增 `fit_status_text()` 按像素截断，窄窗 18/42/69% 分段并简写按钮 |
| 6 | **SFTP 上传只调用一次 `sftp_write` 且忽略部分写入返回值** | 1MB 文件只写入 512KB、MD5 不一致 | 循环写满 chunk，0 字节视为失败；1MB 上传 MD5 一致，断点续传完整 |
| 7 | **`update.ps1` UTF-8 无 BOM，被 Windows PowerShell 5.1 按 ANSI 解析** | 中文引号破坏语法，检查更新永久停在“正在检查”，且不写日志 | 保存为 UTF-8 with BOM；实测正常输出 `UPDATE: OK already-up-to-date` |
| 8 | 检查更新只启动隐藏进程、不读取结果 | 成功后 UI 无回显，用户以为卡死 | 新增 60s 轮询 `update-run.log`，关于窗与状态栏显示“已是最新/下载中/失败/超时” |

另修复测试自身问题：`step0_check.ps1` 仍断言旧标题 `SSH Bridge 3.0*`，已改为 `*ssh-bridge v3*`；`ui_layout_check.ps1` 将 Tab 容器与其子控件 100% 重叠误判为遮挡，已增加祖先链判断。

编译警告从 41 降到 **0**：移除重复 `LUA_USE_WINDOWS`、修正 `winsock2.h/windows.h` 顺序、清理未使用函数/参数/变量与聚合初始化缺字段。

## 五、遗留事项与限制

1. **r10 发布资产未回灌本轮修复**：`output\dist\ssh-bridge-v3-3.0-s13-r10-win64.zip` 与 GitHub Release 内仍是旧 exe、旧 `tools\update.ps1`。本轮所有通过结论对应 `output\build\ssh_bridge3.exe`（SHA `616ACF…`）。对外分发前应重新打包 r11 并更新 `UPDATE.json`。
2. **真实 NFS mount 未验证**：当前只有 Windows 主机，已验证 NFS 服务端口监听；真实 Linux 板卡挂载需硬件环境。
3. **真实 U-Boot / 自动登录未成功**：当前 ok3568 板卡状态未进入 U-Boot，已验证命令能完整执行、错误可读、不崩溃；成功路径需板卡处于可进入 U-Boot/登录提示的状态。
4. **物理鼠标与跨窗口站剪贴板不可用**：自动化窗口站 `foreground=0`，已改用真实窗口消息 `WM_LBUTTONDOWN/UP/DBLCLK` 与桥接动作，业务代码路径与真人操作一致；剪贴板因窗口站隔离未做端到端验证。
5. **DPI 矩阵**：当前仅 150% 缩放实测；100%/125% 未跑完整矩阵。
6. **更新“有新版本”路径**：本轮实测“已是最新”路径；下载、SHA-256 校验、替换、重启路径沿用此前 r9→r10 端到端结果，本轮未再次降级验证。
