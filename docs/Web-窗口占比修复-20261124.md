# Web 控制台窗口占比修复（2026-11-24）

## 结论

仪表盘在 **1024 / 1280 / 1440 / 1920** 四档浏览器宽度下实测：

- 整页内容（`.shell`）占浏览器宽度 **98.4% ～ 99.2%**；
- 右侧终端画框（`.terminal-card`）占 **86.0% ～ 86.3%**；
- 画框内 xterm 占 **85.1% ～ 85.4%**；
- 通道窗口始终在左，终端画框始终在右；
- 900px 高视口下 xterm 高度占 **87.0%**。

所有尺寸均达到“网页窗口不低于 85%”的要求。

## 根因

1. **通道栏固定 196px**：桌面媒体查询把 `.dash` 写死为 `196px minmax(0,1fr)`，浏览器越窄，左侧通道栏占比越大。修复前 1440 宽下终端仅约 84.7%，1024 宽下只有 78.5%。
2. **页面停留在测试夹具**：自动化测试结束后，运行实例没有恢复真实配置，18081 仍是 `output/terminal-test` 的 5 通道、token 启用测试页。用户实际打开时看到的是测试页，而不是截图中的真实 4 通道页。
3. **旧页面不跟随配置变化**：页面 5 秒轮询只刷新通道 RX，顶部通道下拉和 token 状态保持旧值；服务重启或配置切换后必须手动刷新。
4. **1024 宽下通道标题被挤成竖排**：通道栏压缩到 116px 后，标题与“4/4 在线”徽标争抢宽度。

## 修复

- `body.pg-dashboard .dash` 改为
  `grid-template-columns:clamp(112px,calc(15vw - 38px),244px) minmax(0,1fr)`。
  通道栏随视口收缩：1024→116px、1280→154px、1440→178px、1920→244px。
- `.shell` 改为 `max-width:none;width:100%;margin:0`，宽屏不再被 1440px 上限截断。
- 通道标题增加 `white-space:nowrap;flex-shrink:0`，标题与徽标间距改为 6px，1024 宽下不再竖排。
- 5 秒轮询加入 `configDrift()`：`token_required` 或服务端通道名列表变化时提示“配置已变化，正在刷新页面”并自动重载。
- 测试结束后恢复真实配置 `C:\Users\admin\.ssh-bridge\ssh_bridge_config.json`，当前运行态为 **4 通道、token 未启用、可写**。
