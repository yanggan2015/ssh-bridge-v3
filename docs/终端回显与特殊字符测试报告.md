## 2. 测试方法

- 通过 Win32 UI 桥切换左侧通道树，真实激活对应终端窗格。
- 用 `term.input` 走应用自己的输入路径：UTF-8 文本 → `TerminalView::type_text` → `IBridge::write`。
- shell 通道执行 `printf 'OUT<%s>END\n' '<payload>'`。命令回显里只有 `OUT<%s>END` 格式串，断言 `OUT<真实 payload>END`，因此命中一定是远端执行后的输出，不是输入行回显。
- 串口回环直接发送 payload，回环端点原样回送；短行断言 tail，长行断言 `tx+ == rx+`。
- 每项都要求业务结果与 `tx_bytes/rx_bytes` 同时增长，不只检查 `ok:true`。
- shell 通道先发 `set +H`，避免长行里的 `!` 触发 Bash 历史展开。

## 6. 发现并修复的缺陷

### 6.1 BMP 外字符被截成 16 位

- 现象：应用输入 `😀🚀`，远端实际收到 `U+F600 U+F680` 两个私用区字符。
- 根因：`TerminalView::type_text` 已正确解析 4 字节 UTF-8 得到 U+1F600，却调用 `encode_char()`，内部把码点强制转成 16 位 `wchar_t`。
- 修复：新增 `term::encode_codepoint()` 直接按 Unicode 码点生成 1/2/3/4 字节 UTF-8；`type_text` 改用它。
- 回归：SSH、COM3 的 Emoji、ZWJ、组合字符全部 PASS。

### 6.2 满最后一列后覆盖末格

- 现象：161 列终端里输入 240 字符，输出只剩前 161 字符，后面的字符全部覆盖最后一格。
- 根因：`AnsiScreen::put_cp` 把光标夹在 `cols-1`，没有 xterm 的“延迟换行”状态。
- 修复：新增 `wrap_pending_`；写满最后一列后置位，下一个字符才换行；CR/LF、退格、光标定位会清除该状态。
- 回归：新增 `T4U-11 满最后一列后延迟换行不覆盖`；`--selftest all` ALL PASS；长行在 161 列处正确折成两行。

### 6.3 真实串口打开成功但 `rx_bytes` 恒为 0

- 现象：COM3/COM5 在应用内状态为 `ready`，发送后 `tx_bytes` 增长，`rx_bytes` 始终为 0；同一时刻最小 `.NET SerialPort` 脚本能立即读到 `root@ztl:~#` 和 `ok3568 login:`。
- 根因：应用旧读泵先 `WaitCommEvent(EV_RXCHAR)`，再把同一个 `hEvent` 交给 `ReadFile`，并在 150ms 超时后 `CancelIoEx` 重发。最小 Win32 探针复现：`WaitCommEvent` 已返回 `mask=0x1`，随后 `ReadFile` 仍超时；CH340/CP210x 在这条“先等事件、重置同一事件、再读”的路径上丢读完成。
- 修复：删除 `WaitCommEvent`，改为持续挂一个 overlapped `ReadFile`；数据到达即 `GetOverlappedResult` 交给 ring，然后立即重挂。停止时只取消一次 pending 读，不再每 150ms 取消重发。
- 回归：修复后 COM3 13/13、COM5 ASCII 7/7、SSH 两条各 13/13、回环 12/12。

## 8. 边界

- `tail` 只保留终端最后两行非空文本，长行用尾部标记或 `tx+ == rx+` 断言，不要求整行出现在同一个数组元素里。
- 纯尾部空格会被显示层裁掉；用例用 `END` 后缀验证空格确实传输。这是渲染裁剪，不是输入丢字。
- COM5 板端 `LANG=C` 且没有 UTF-8 locale，Unicode 在板端即被改成 `?`；最小脚本直发可复现，不能用它评价应用 UTF-8 编码。
- COM5 登录前曾遇到板端 `rz`/ZMODEM 接收器占用 console；发送终止序列后回到 shell。这不是应用串口读问题。
- 本次验证终端输入/回显/换行与串口链路，不覆盖板卡业务命令语义。

### bracketed paste（r16）

现代 shell 会发 `ESC[?2004h` 开启 bracketed paste。应用原先未解析该模式，多行粘贴会把每个换行当回车提交，逐行执行。r16 处理：

- `AnsiScreen` 记录 `?2004h/l` 状态；
- `encode_paste(utf8, bracketed)` 在 bracketed 模式保留 LF，并用 `ESC[200~` / `ESC[201~` 包裹，普通串口/未开启该模式的 shell 仍把换行转 CR；
- 自测 `T4U-13` 断言模式开关、普通换行和包裹字节。

真实 SSH `tests\terminal_bracketed_paste.py`：发送两条命令的 bracketed 序列，Enter 前无输出，Enter 后输出 `BP_A BP_B`，ALL PASS。锁屏会话下系统剪贴板不可写，UI 级 `term.paste` 无法复现，本项以自测字节与真实 shell 行为验收。
