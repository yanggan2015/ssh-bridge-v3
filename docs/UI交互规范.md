# UI 交互规范（v3）

## 0. 一条硬规则：能选就不让输

凡是“取值来自有限集合、或存在常见取值”的字段，一律用**下拉框**，不让用户凭记忆敲：

- 枚举型（串口/SSH、数据位、校验、停止位、流控、行尾、编码）：只读下拉（`CBS_DROPDOWNLIST`）。
- 半开放型（设备、波特率、SSH 端口、term、超时、列/行、保活）：**可编辑下拉**（`CBS_DROPDOWN`）——
  下拉给常用值 + 真实探测值，用户想填自定义也直接敲；两者是同一个框，不做“下拉 + 旁边再放一个输入框”。
- 只有真正无法枚举、且必须由用户表达的字段才保留纯输入：通道名、主机、用户名、密码、搜索词。

判断顺序：能列举 → 只读下拉；能列举但允许特例 → 可编辑下拉；不能列举 → 输入框（必要时给示例占位）。

## 1. 表单（通道管理）

| 字段 | 形态 | 候选来源 |
| --- | --- | --- |
| 类型 | 只读下拉 | 串口 / SSH |
| 设备 | 可编辑下拉 | `QueryDosDevice` 实时枚举 COM1…COM256 + `loop:ai/loop:demo`；「刷新」重新枚举 |
| 波特率 | 可编辑下拉 | 9600 / 19200 / 38400 / 57600 / 115200 / 230400 / 460800 / 921600 / 1500000 / 2000000 / 3000000 |
| 数据位 / 校验 / 停止位 / 流控 / 行尾 / 编码 | 只读下拉 | 固定协议枚举 |
| SSH 端口 | 可编辑下拉 | 22 / 2022 / 2222 / 8022 / 52222 |
| term | 可编辑下拉 | xterm-256color / xterm / vt100 / ansi / linux |
| 超时(ms) | 可编辑下拉 | 1000 / 3000 / 5000 / 10000 / 30000 |
| 列 / 行 | 可编辑下拉 | 80·100·120·160·200 / 24·30·32·40·48 |
| 保活(s) | 可编辑下拉 | 0 / 3 / 5 / 10 / 30 |
| 名称 / 主机 / 用户 / 密码 | 输入框 | 无法枚举，必须自由输入 |

## 2. AI 可控性要求（与选择化同等重要）

- 每个下拉必须有稳定 id，`/ui-tree` 要能看到 `items` 列表，AI 才能“先看选项再选”。
- `select`（按序号）与 `set_text`（填自定义值）都必须生效；`CbsDropdown` 的自定义值不在列表里时，
  业务读取要回退到编辑区文字，不能因为 `CB_GETCURSEL == -1` 就读成空。
- `click` 对下拉应展开候选（`CB_SHOWDROPDOWN`），而不是只挪焦点。
- 下拉展开后是独立 `ComboLBox` 窗口；遮挡检查要把它内部 EDIT 当容器子件排除，不能误报。

## 3. 反馈

- 选择后立即在表单内可回读（`/state.ui.dialog`），保存后状态栏给“通道已生效：x · N ms · 时间”。
- 「刷新」类动作要有可量化回执，例如「已刷新：发现 3 个串口」。
