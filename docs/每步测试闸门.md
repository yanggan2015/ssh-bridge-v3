# 每步测试闸门（硬性规则）

**任何一步，必须先把该步的测试功能列全、跑全绿、代码整理干净，才允许进入下一步。**

## 三步出口闸门

每步结束时，三份东西必须同时成立：

| 闸门 | 内容 | 载体 |
|---|---|---|
| ① 测试清单 | 该步要测什么，逐条编号、逐条可判定 | `tests/CHECKLIST_stepN.md` |
| ② 全量通过 | 清单每一行都是 PASS；自动化脚本退出码 0 | `tests/stepN_check.ps1` |
| ③ 代码整理 | 零警告编译、无 TAB、无行尾空白、无超长行、无死代码 | `scripts/quality_gate.ps1` |

三者齐了才 `git commit`；提交信息按 `docs/编程规范.md` 的四段式，标题用 `<type>(stepN): <一句话结论>` 并在正文写「怎么验」的闸门结论。

## 通用必测项（每步都测，不允许豁免）

| 编号 | 项目 | 判定 |
|---|---|---|
| G-0 | 形态 | 界面与桥同进程：没有为本机 UI 数据新开回环端口，任务管理器里只有一个 desktop.exe |
| G-1 | 编译 | `-Wall -Wextra` 下 error=0 且 warning=0 |
| G-2 | 启动 | 进程起来，5 秒后仍存活，主窗口标题正确 |
| G-3 | 关闭 | 走规定路径关闭（步骤 1 起为托盘退出），进程退出码 0 |
| G-4 | 残留 | 退出后无残留进程，端口全部释放（`netstat` 核） |
| G-5 | 崩溃 | 全程无 Windows 错误对话框、无 access violation |
| G-6 | 代码整理 | `quality_gate.ps1` 全部 PASS |
| G-7 | 提交 | 工作区干净，提交信息含 `step N` 与闸门结论 |

## 各步专属清单（逐步补全，不提前写未做的事）

- S0 工程地基：`tests/CHECKLIST_step0.md`（13 项）
- S1 配置 / 环形日志 / 串口桥：`tests/CHECKLIST_step1.md`（18 项，含 `--selftest`）
- S2 SSH 出站链路：`tests/CHECKLIST_step2.md`（11 项，paramiko 测试服务器）
- S3 窗口壳 + 生命周期：`tests/CHECKLIST_step3.md`（14 项）
- S4 终端窗格：`tests/CHECKLIST_step4.md`（19 项，`output\ui_terminal.json` 观测面）
- S5 AI 可控桥接：`tests/CHECKLIST_step5.md`（41 项，HTTP 端点 + 逐控件动作 + 反向用例）；`agent.enable=false` 时 G-4 仍成立
- S10 Agent 双面：设备面与 UI 桥分开验收。设备面必须证明 **关闭 18096 后 18081 仍可完整控板**；UI 桥必须证明 **关闭 18081 后 18096 仍可操作窗口**；并扫描 18081 路由无 18096/UI 调用。清单到该步再建，不提前写未做的事
- S6 通道管理 / 手术式热应用、S7 偏好与快捷键：到该步再建，不提前写未做的事
- S8–S13（扩展）：每步一份清单，出口条件同本体

## 失败处理

- 任何一项 FAIL：**不得提交**，回到实现修到全绿；若确属设计问题，先改设计文档与框图，再改代码。
- 不允许"先记下、下一步再修"——闸门的含义就是本步不带病过关。
