# 工程目录与产物说明

本文说明源码、测试、脚本与产物的边界。产物的逐目录清单以 `output/README.md` 为准；`output/` 整体被 `.gitignore` 排除，不入库。

## 根目录

| 路径 | 职责 | 是否入库 |
|---|---|---|
| `src/` | 应用源码：`app` 装配层、`core` 领域核心、`ui` Win32 界面、`services` 可插拔服务、`third_party` 第三方源码 | 是 |
| `tests/` | 可重复执行的验收脚本与 CHECKLIST；以 `stepN_check.ps1`、专项矩阵和 EADK 检查为主 | 是 |
| `scripts/` | 构建之外的发布、打包、质量闸门脚本（`package.ps1`、`publish-release.ps1`、`quality_gate.ps1` 等） | 是 |
| `docs/` | 设计、规范、验收报告与文档索引；入口见 `docs/README.md` | 是 |
| `share/` | 随包分发的 `tools/` 与 `skills/`；运行期由共享服务对外提供 | 是 |
| `skills/` | 项目自带 Skill 源材料 | 是 |
| `shots/` | 用户既有截图材料 | 否（保留原位） |
| `work/` | 运行期日志与共享根，`work/logs/` 被忽略 | 部分 |
| `output/` | 构建、测试、截图、安装包与历史验收证据 | 否 |
| `Makefile`、`README.md`、`LICENSE` | 构建入口、项目说明、许可证 | 是 |

## 源码分层

```text
src/
  app/        唯一装配层：main、生命周期、服务编排
  core/       与界面无关：config / bridge / logbuf / util / channel_core
  ui/         Win32 界面：shell / terminal / dialogs / sftp / services / tray / aibridge
  services/   扩展服务：inbound / web / agent / relay / tftp / nfs / share /
              tcpfwd / tunnel / discovery / board_actions / script
  third_party/ mongoose / Lua / winnfsd / win_ui_bridge
```

依赖方向固定为 `ui → core`、`services → core`，`core` 不反向依赖；只有 `app` 可以同时装配三层。

## 产物分区

| 目录 | 性质 | 处理规则 |
|---|---|---|
| `output/build/` | 当前构建产物 `ssh_bridge3.exe` | 可重建；以 SHA-256 标识当前二进制 |
| `output/terminal-test/` | 现行运行工作目录与测试夹具 | 回归必需，不随意移动；内含 5 通道夹具与大体积历史证据 |
| `output/webtest/` | 现行 Web/Agent 回归脚本与 19 套件编排器 | 回归入口，不移动 |
| `output/ux-audit/` | 现行回归结果、日志与截图 | 保留最近一轮；旧轮次可打包归档 |
| `output/feature-inventory/` | 141 条功能台账、Agent 74 项、12 页 DOM 目录 | 当前盘点证据，保留 |
| `output/dist/` | 发布 zip、SHA-256、UPDATE 清单 | 发布证据，保留 |
| `output/audit*.log` | 2026-11-24 代码审计的构建、告警、加固、全量日志 | 本轮审计证据，保留 |
| `output/step*/`、`output/s*/`、`output/p6-*/`、`output/ui-full-audit-*/`、`output/layout*/`、`output/inventory*/` | 分阶段历史验收 | 被历史脚本或文档按路径引用，原位保留 |
| `output/archive/` | 已确认无引用的历史副本 | 只归档，不删除 |

`output/README.md` 记录了每个子目录是否被脚本硬编码引用。任何“清理”都应先查引用，再只处理 `archive/` 或确认无引用的旧轮次，不做递归删除。

## 新增文件落点

| 类型 | 落点 |
|---|---|
| 业务代码 | `src/<层>/<模块>/`，不跨层放实现 |
| 验收脚本 | `tests/`；若属于 Web 套件体系，放 `output/webtest/` 并在 README 注明 |
| 设计与验收文档 | `docs/`，并登记到 `docs/README.md` |
| 构建/运行证据 | `output/<主题>/` 或 `output/audit-*.log`，不塞进源码目录 |
| 发布脚本与模板 | `scripts/` |
| 随包工具 | `share/tools/`、`share/skills/` |

## 命名与保留

- 目录和文件按“主题 + 日期/阶段”命名，不使用 agent id、会话 id、任务 id。
- 当前入口脚本保持稳定文件名；历史副本进 `archive/` 时保留原相对结构，便于回取。
- 构建产物不手工改二进制；需要新基线时重新 `make` 并记录大小与 SHA-256。
- 版本结论以根 `README.md` 的“当前状态”与 `output/ux-audit/full-suite-summary.json` 为准。
