## 2. 关键决策（改之前先看这里）

| # | 决策 | 理由 | 反例（已被否决） |
|---|---|---|---|
| D1 | **单进程**：界面 + 桥 + 服务都跑在 `desktop.exe` | 同进程可直读 ring，零序列化、零额外端口 | 界面走本地 HTTP 轮询（多一跳、易阻塞） |
| D2 | desktop 是**原生 Win32 本体**，不是网页壳 | 端口只对进程外开放；窗口只是进程的界面 | `DESIGN.md` §1.3 的 WebView2 蓝本（旧稿，v2 已弃） |
| D3 | **一路通道一个 ring，只有 RX 泵线程写** | 设备输出只有一处来源，多读者天然一致 | 下行字节写进 ring（会自我回显、日志失真） |
| D4 | 读者**各持游标拉取**，写者只 `notify_seq++` + kick | 慢读者只丢自己，不堵写者 | RX 线程直接写 UI buffer（加锁、背压、双份数据） |
| D5 | **不做本地回显** | 回显是板端真实 RX 字节 | “先画后校”的乐观回显（双字符、桌面与网页不一致） |
| D6 | 扩展**只准加、不准改本体接口** | 保证本体 S7 可独立交付 | 扩展里塞私有路径/私有 ring |
| D7 | 步骤切分按**产品形态**，非按代码模块 | 每步都“能看见效果、能独立验收” | 按 v2 文件清单切（职责交错、无法单测） |
| D8 | **每步清单全量 PASS 才进下一步**；每步一笔提交 | 防止“越写越乱”，回滚粒度小 | 攒一大笔再提交 |
| D9 | warning **能修必修**，第三方头只做局部 suppress 并注明 | 保持编译输出干净，问题不被埋 | 全局 `-w` 掩盖 |
| D10 | 入站**共享网关**（用户名=通道名），不做每板独立口 | 一个进程一个 gateway，入站与本地共用同一条出站链路 | 每板 listen（多实例抢 2222、内容不同步） |
| D11 | 串口设备名支持 `loop:` 端点（内置回环，不开 Windows 句柄） | 本机 CH340 两口无内部回环线，回环验收必须可无人值守复现 | 必须外接杜邦线才能测（不可自动化、机器相关） |
| D12 | 自检结果写文件（`output\selftest\result.txt`）再 `AttachConsole` 回显 | `-mwindows` 子系统没有可用 stdout，管道抓取必丢 | 让测试脚本解析 exe 的 stdout |
| D13 | 本体 exe **全静态链接**（`-static`），不许依赖 msys2 的 DLL | 交付物要能脱离 MSYS2 环境双击运行；否则 PATH 里没有 mingw64 就静默起不来 | 只加 `-static-libgcc -static-libstdc++`（仍吃 `libcjson-1.dll`、`libwinpthread-1.dll`） |
| D14 | SSH 用 **libssh**（静态 `libssh.a` + `-DLIBSSH_STATIC`） | 与设计稿一致；一个库同时覆盖客户端（S2）与后续入站网关（S8） | libssh2（另一套 API，还得多引一个依赖） |
| D15 | SSH 验收用 **paramiko 测试服务器**（`tests\tools\ssh_test_server.py`） | 能精确控制「拒绝密码 / 杀进程拔网 / 同端口重启」三种场景，比接真板子可复现 | 只测真机（机器相关、无法无人值守） |
| D16 | UI 状态写 `output\ui_state.json`（每秒一次）当观测面 | 树/状态栏文本无法从外部稳定读取；给闸门与后续网页/Agent 一个只读快照 | 靠窗口标题传状态（信息量太小） |
| D17 | 托盘动作在闸门里用 `WM_APP+1/2` 模拟 | 真实托盘点击无法脚本化；消息与双击/菜单走同一分支，等价性够 | 引入 UI Automation 点托盘（依赖 shell 位置与环境） |

## 3. 踩坑清单（可复现）

| 现象 | 根因 | 处理 |
|---|---|---|
| Bash 工具在本机直接拒绝执行 | 宿主为 Windows，只提供 PowerShell | 一律用 `PowerShell` 工具；不要写 Bash 语法 |
| `FindWindowW(cls, $null)` 拿不到窗口，`hwnd=0`，`WM_CLOSE` 发不出去 | PowerShell 把 `$null` marshal 成空串，等同按标题 `""` 匹配 | 轮询 `$proc.MainWindowHandle`，再 `PostMessageW(hwnd,0x0010,0,0)` |
| Makefile 报 “missing separator” | 编辑器把 recipe 缩进写成空格 | `Makefile` 顶部 `.RECIPEPREFIX = >`，recipe 用 `>` |
| mermaid 图在 A4 竖版里右侧被裁 / 字号缩到 5px | svg 带 inline `max-width:Npx` 压过 CSS；12 个节点的行宽远超栏宽，只能整体缩小 | 打印 CSS 用 `!important` 强制 `max-width:100%`；阶梯图分组细分到 6 段、标签缩短、`htmlLabels:false`，每行≤6 节点 |
| 节点里的中文标签被框裁掉（“窗口壳 / 托”） | mermaid 用 HTML label 测量宽度，对中文估窄，foreignObject 再裁切 | 图表 init 里关闭 `htmlLabels`，改用 SVG 文本测量 |
| 无头截图里 mermaid 没渲染，只有源码 | 截图发生在异步渲染之前 | Chrome 加 `--virtual-time-budget=20000`，或先 `wait_for_selector('svg')` |
| mermaid 33 节点 + 38 条边渲染成“蜘蛛网”，文字缩到看不清 | dagre 自动布局在有环/跨组边时摊开 | 阶梯图改为**分层带、组内不连线**；连线细节放详细设计文字 |
| 用 `~~~` 隐形链把节点压成一列，结果全成横排大空白 | 隐形链约束了 rank，方向与预期相反 | 放弃隐形链，直接不画边 |
| `block-beta` 分组标题不渲染、节点互相压字 | 该版本（11.4.1）对中文分组块支持不完整 | 弃用 block-beta，回到 `flowchart + subgraph` |
| PDF 里标题落页底、图掉下一页 | 默认 CSS 无分页控制 | `docs\pdf-print.css`：`h2{break-after:avoid}`、`.mermaid{break-inside:avoid}`、`.pb{break-before:page}` |
| PDF 分组底色米黄，与绿/橙/灰语义冲突 | mermaid `default` 主题的 cluster 底色 | 每张图加 `%%{init: theme base, clusterBkg white}%%` |
| markdown2pdf 安装失败：`greenlet` 编译要求 MSVC | `requirements.txt` 钉 `playwright==1.40` → `greenlet==3.0.1` 无 cp313 轮子 | venv 里改装最新 `playwright`，再 `python -m playwright install chromium` |
| `@page{size:A4 landscape}` 不生效 | Playwright 传了 `format='A4'`，覆盖 CSS | 未做横版；需要时改转换参数而不是改 CSS |
| `git status` 显示中文文件名为八进制转义 | git 默认 `core.quotepath=true` | 命令加 `-c core.quotepath=false` |
| 每次提交都提示 `LF will be replaced by CRLF` | Windows 下 autocrlf | 无害；文档统一 LF 落盘，忽略该警告 |
| 桌面工具抢焦点（360 浏览器全屏）遮住 Chrome | 第三方全屏窗口置顶 | Alt+Tab 切回；或直接用无头 Chromium |
| `cu.scroll` 传像素报 `CU_SCROLL_DELTA` | CU 的 scroll delta 只接受 -10…10 档位 | 用档位值滚动，或改为截图核对 |
| `cu.type` 输入 `ssh-bridge` 丢了连字符 | CU 键盘输入对部分符号处理有损 | 改用剪贴板/直接写文件，避免依赖键盘输入长文本 |
| `--selftest` 第一次跑就卡死（ring 落盘环节） | `disk_open()` 持 `disk_mu_` 又调 `disk_close()`，同一非递归 mutex 自锁 | `disk_open` 先调 `disk_close()`（自带锁），再取锁写 `disk_` |
| `stop()` 后再 `start()`，下行全部被吞（`restart=0`） | `stop()` 里 `cmds_.close()` 标记队列关闭，`start()` 没重开 | `start()` 开头 `cmds_.reset()`；此类“生命周期复位”必须与 stop 成对 |
| T1-3 自检误报丢字节 | 拿本轮增量去比对累计 stream | 区分口径：`stream += part`；dropped 时比对 `stream` 末 cap 字节，否则比对 `part` |
| 串口自检看起来“挂起 / TIMEOUT” | `-mwindows` GUI 子系统 + `Start-Process -Wait` 行为不稳，且常有上一轮残留进程 | 只认 `Start-Process` + `Start-Sleep` + 读 `output\selftest\result.txt`；跑闸门前先 `taskkill /IM ssh_bridge3.exe /F` |
| T1-5 / T1-7 无 PASS 行 | `--selftest all loop:selftest` 只有 2 个参数，`all` 分支写的是 `args.size()>=3` 才跑串口 | `all` 分支先判 `loop:` 前缀再决定；参数个数分支条件必须同时覆盖 loop 与 A/B 两种形状 |
| 本机 A/B 串口互发永远失败 | COM3/COM4 是两个独立 CH340（`VID_1A86&PID_7523`，`0&3`/`0&4`），无内部回环；COM5 是 CP210x | 改走内置 `loop:` 端点验证 RX 泵→ring→writer 全链路；真机用例保留 A/B 分支 |
| 提交信息里有弯引号 `“”` 报 `pathspec ... did not match` | PowerShell 把弯引号当字符串定界符截断命令 | 提交信息只用直角引号「」或普通引号 |
| Makefile 报 “missing separator”（多源文件改造时） | 用脚本重写 `SOURCES` 时漏了续行反斜杠 | `SOURCES := \` 起头，每条以 `\` 结尾，末条不带；改完立刻 `make` 验证 |
| 一次 `git add -A` 把临时脚本、自检产物、后续模块全塞进提交 | 提交时图省事 | 一律按路径 `git add <文件>`；`output\selftest\` 已进 `.gitignore`，临时脚本放 `%TEMP%` 或即时删除 |
| 刚编译完立刻跑闸门，G-0/G-3 等 9 项 FAIL | 上一轮窗口实例还活着，或编译产物被占用 | 闸门脚本前先 `taskkill`；重跑一次即全绿（本页记录的 ALL PASS 均为清理后结果） |
| `-SkipBuild` 模式下自检与窗口检查全 FAIL（进程活着、没窗口、没 `result.txt`） | exe 动态依赖 `libcjson-1.dll` / `libwinpthread-1.dll`，脚本不设 `PATH` 时装载失败，GUI 子系统连错误框都弹不出来 | Makefile 改 `-static -lcjson` 全静态链接；用 `objdump -p exe \| Select-String 'DLL Name'` 复核只剩系统 DLL（D13） |
| 链 libssh 全部报 `undefined reference to __imp_ssh_*` | 头文件在 Windows 下默认 `__declspec(dllimport)`，没定义 `LIBSSH_STATIC` | CXXFLAGS 加 `-DLIBSSH_STATIC` |
| 只写 `-lssh` 仍解析到 `libssh.dll.a`，或静态库缺符号 | `-l` 优先匹配 import lib；`libssh.a` 自身还需要 zlib/openssl/iphlpapi | 直接给全路径 `$(MINGW)/lib/libssh.a -lz -lcrypto -lws2_32 -lcrypt32 -lbcrypt -liphlpapi` |
| `libssh.a` 链接报 `undefined reference to if_nametoindex` | 该符号在 iphlpapi，不在 ws2_32 | 追加 `-liphlpapi` |
| 测试配置写 `config.json` 却读到了用户目录的配置 | `config_load` 顺序是 cwd 的 `ssh_bridge_config.json` → `%USERPROFILE%\.ssh-bridge\` → cwd 旧名 `config.json` | 测试目录必须写 `ssh_bridge_config.json`（别名在最后才查） |
| S3 落地后 step0/step1 闸门 T0-10/G-3 失败 | 点 X 改成隐藏到托盘，不再 `DestroyWindow`，旧断言「`WM_CLOSE` 后进程退出」失效 | 两个脚本改为：`WM_CLOSE` → 断言隐藏且存活 → 发 `WM_APP+2` → 断言退出码 0（语义变更已写进 CHECKLIST_step3 §3.5） |
| `HTREEITEM` 直接 `static_cast` 编译失败 | `SendMessageW` 返回 `LRESULT`（整数），转指针必须 `reinterpret_cast` | 用 `reinterpret_cast<HTREEITEM>` |
| 终端里出现 `14:29:23.116 RED-ANSI`（时间戳没剥净，混进转义序列后） | 原实现只在"行首"剥时间戳，但 ANSI 序列之后的行首同样算行首 | `strip_timestamps` 加 `esc_state_`（跟踪 ESC/CSI/OSC）+ `at_line_start_`（本行尚无可见字符，ANSI 不改变它）+ `carry_` 暂存跨块半截时间戳 |
| 闸门给搜索框 `SetWindowTextW` 后 `search_hit` 一直 false，但消息与 `find_typed` 都正常 | 跨进程 `SetWindowTextW` 对 EDIT 不生效（`WM_SETTEXT` 的字符串指针无法跨进程编组），且 EDIT 不为程序化设值补发 `EN_CHANGE` | 闸门改成逐字 `SendMessageW(search, WM_CHAR, ...)`，让 EDIT 自己发 `EN_CHANGE`；CHECKLIST_step4 §3.4 记下该约束 |
| 搜索框逐字输入后只命中第一个字符（`hit.len=1`） | 每次 `find` 都从"上一次命中 + 1"继续找，旧锚点把后续输入挡在后面 | `Pane::find(..., restart)`：搜索框输入时 `restart=true`，从视口当前位置重新找；空串则 `clear_search` |
| `find_typed` 有 1 字节越界写 | `WideCharToMultiByte(...,-1,...,buf,need)` 会写 `need` 字节（含终止符），缓冲区只申请了 `need-1` | 先申请 `need`，转完 `resize(need-1)` |
| T1-8 偶发 `exit=-1073741819`（0xC0000005），且自检结果文件为空 | `RunSelftest` 先 `fclose(stdout)` 再 `freopen("CONOUT$")`——对已关闭的流 `freopen` 是未定义行为；`freopen` 失败时 `printf` 写空指针也会崩 | 去掉 `fclose`，直接 `freopen` 摘流；失败时把 stdout 接到 `NUL` 兜底 |
