# S12 详细设计：MobaXterm 式工作台重构

> 本文件是 `docs/详细设计.md` 的 S12 专章。目标不是补 S11 的小项，而是把“继电器 + 文件服务”合一面板拆开，把常用入口抬到菜单栏，并按 MobaXterm 的形态重排左侧通道管理与板卡按钮。
>
> 设计原则：先理解用户的操作路径，再决定控件位置；能用下拉框表达的，不做纯输入框；所有控件必须有稳定 id、可被桥接读取和操作；验收必须逐控件真机点击并检查遮挡。

## 1. 目标与边界

### 1.1 本轮必须完成

1. 继电器配置独立成窗口，不再和 TFTP/共享/NFS 混在一起。
2. 文件服务独立成窗口，保留 S11 已验证的 TFTP/HTTP/NFS 行为。
3. 常用入口提升到菜单栏顶级项：继电器、文件服务、板控按钮。
4. 左侧通道管理器按 SSH / 串口 / Telnet / PowerShell 分类；不再有单独的“通道”根节点。
5. 左侧建立“通道 / 文件”选项卡骨架；本轮先把结构、切换和状态做对，文件内容按通道类型后续接入。
6. 板卡专属按钮：继电器绑定、上电/下电/重启/进升级模式、板端命令、本机命令、Lua 脚本。
7. “生成按钮”落到具体步骤：在继电器绑定页，按当前继电器与通道一键生成标准 `power_on` / `power_off` / `reboot` 三个板卡按钮；在脚本页提供“进升级模式”生成按钮。
8. 所有新增控件不互相遮挡，窗口缩放后仍不遮挡；验收时逐控件真实操作。

### 1.2 本轮不做

- Telnet / PowerShell 的完整协议实现。左侧先建立分类和空分类提示；协议通道放到后续步骤，避免把 UI 重构和网络/进程终端混在一起。
- 左侧“文件”页的完整文件浏览与拖拽上传下载。本轮做选项卡、按通道类型显示说明和占位；SSH 远端文件系统、串口 `share` 目录、PowerShell 当前目录在下一阶段接入。
- 继电器设备枚举的自动发现。仍以配置中的设备清单为准，串口下拉列出本机存在的 COM。

### 1.3 与 S11 的关系

S11 已验证的行为是回归基线，拆窗不能改变：

- TFTP 端口 69、共享 HTTP 18082、NFS `/share` 与 `/mnt/share`；
- 中文路径、只读拒绝、端口冲突中文提示；
- 配置保存不互相覆盖；
- 关闭面板只关窗口，服务继续运行；
- “全部停止”后端口释放；
- 主窗口“断开”能释放 COM。

## 2. 信息架构

### 2.1 主窗口

```
┌ 菜单栏：文件 | 视图 | 继电器 | 文件服务 | 板控按钮 | SFTP | 帮助
├ 工具栏：[新建] [刷新] [重连] [断开] [清屏] [收起/展开]  [搜索框]
├ 左侧（宽窗展开；窄窗自动收起，可按钮切换） ┌ 通道 / 文件 选项卡 ┐
│  通道页：                │ SSH (2)           │
│                          │    demo1          │
│                          │    demo2          │
│                          │ 串口 (4)          │
│                          │    loop1 ...      │
│                          │ Telnet (0)        │
│                          │ PowerShell (0)    │
│  文件页：按通道类型说明   └───────────────────┘
├ 板卡按钮条：[上电] [下电] [重启] [进升级模式] ...（板卡专属，可隐藏）
├ 终端工作区（单/双/四窗格）
└ 状态栏：通道统计 | 当前通道 | 终端时延/信息 | 最近动作回执
```

要点：

- 左侧通道管理器默认展开。客户区宽度小于 `820 DIP` 时自动收起，终端铺满右侧；回到 `820 DIP` 以上自动恢复。工具栏第 6 个按钮（`btn.toggleTree`）与 `Ctrl+B` 可随时手动收起/展开；窄窗手动收起后拖宽仍会自动恢复。本条为 S13-r6 对“固定不折叠”的修订。
- 工具栏第六个按钮为“收起/展开”，新建/刷新/重连/断开/清屏仍在前五位。搜索框仍在右上，窄窗下自动缩短占位文案。
- 最小窗口放宽到 `480 × 480 DIP`；工具栏、状态栏与搜索框按 `900 / 640 DIP` 断点压缩，窄窗下隐藏快捷键提示与“搜索”标签。
- 板卡按钮条只在当前通道有启用按钮时显示；没有按钮时终端上移，不保留空白条。
- 顶级菜单不把常用功能藏在“工具”二级菜单里。

### 2.2 顶级菜单

| 顶级项 | 内容 |
|---|---|
| 文件 | 新建串口通道、新建 SSH 通道、编辑/删除当前通道、重新加载配置、隐藏到托盘、退出 |
| 视图 | 刷新、重连、断开、单/双/四窗格、复制/粘贴、加载历史、清屏、跳到搜索、下一个命中 |
| 继电器 | 直接打开“继电器配置”窗口 |
| 文件服务 | 直接打开“文件服务”窗口 |
| 板控按钮 | 直接打开“板控按钮”窗口，默认落在“按钮脚本”页 |
| SFTP | 直接打开当前 SSH 通道的 SFTP 面板 |
| 帮助 | 关于 |

`menu.relay.config`、`menu.fileService.config`、`menu.boardButtons.config`、`menu.sftp` 都要注册到桥接。

### 2.3 左侧选项卡

- `SysTabControl32`，两个页签：“通道”“文件”。
- “通道”页是 `TreeView`，四个固定分类节点：
  - `SSH (n)`：`kind == "ssh"`；
  - `串口 (n)`：`kind == "serial"`；
  - `Telnet (n)`：本轮通常为 0；
  - `PowerShell (n)`：本轮通常为 0。
- 分类节点不是通道，选中分类时终端保持当前通道，状态栏显示“当前：未选通道”。只有选中通道叶子才切终端。
- 分类节点默认展开；没有子项的分类显示为灰色说明，不允许误当作通道。
- “文件”页已接入最小可用的真实文件浏览（自绘 `FileBrowser` 子窗口，类名 `SB3_FileBrowser`）：
  - 串口：浏览本机共享目录。根目录取 `tftp.root`，为空时用 `{project_root}/work/share`；相对路径基于 `project_root`。列“名称/类型/大小”，目录优先；顶部只读路径、`上级`、`刷新`；双击目录进入，双击文件用系统默认程序打开；根部 `上级` 禁用。
  - 列表只显示目录与普通文件，过滤隐藏/系统属性项和 `.tmp/.log/.bak/.swp/.swo/.dmp/.obj/.o/.pdb/.ilk/.exp/.lib/.pyc/.class` 等系统垃圾后缀；最多 500 项，底部显示“共享目录 · N 项”。
  - SSH：侧栏不内嵌远程列表，显示“SSH 通道：使用 SFTP 面板浏览远端文件”和`打开 SFTP`按钮，复用现有 SFTP 面板。
  - 无通道显示“未选择通道”；其他类型显示“该通道类型的文件视图尚未接入”。
  - PowerShell 当前目录、Telnet 远端列表仍在后续阶段接入。
- 选项卡切换只影响左侧内容，不重建终端、不清日志。

## 3. 继电器配置窗口

### 3.1 窗口形态

- 独立顶层窗口，类名 `SB3_RelayPanel`，标题“继电器配置 — SSH Bridge 3.0”。
- 客户区设计尺寸约 `1120 × 620` DIP；最小尺寸 `980 × 620` DIP。150% DPI 下实测 1702 × 986，完整落在 1920 × 1040 工作区。
- 顶部是 `SysTabControl32`，三页：
  1. 继电器设备
  2. 板卡绑定
  3. 按钮脚本
- 底部固定一条消息区与“关闭”按钮。消息区不被任务栏遮挡；窗口高度不足时内容区滚动或压缩，不能压到消息区。
- 所有控件 id 前缀 `relay.`，设备页 `relay.dev.*`，绑定页 `relay.bind.*`，脚本页 `relay.script.*`。

### 3.2 页 1：继电器设备

字段（能用下拉框的都用下拉框，允许下拉 + 输入）：

| 控件 id | 类型 | 说明 |
|---|---|---|
| `relay.dev.name` | 下拉 + 输入 | 设备名，已有设备可选，也可输入新名 |
| `relay.dev.port` | 下拉 + 输入 | Windows 串口，列出本机 COM，保留手输 |
| `relay.dev.linux` | 输入 | Linux 串口，跨平台配置保留 |
| `relay.dev.channels` | 下拉 + 输入 | 通道数，常用 1/2/4/8 |
| `relay.dev.baud` | 下拉 + 输入 | 9600/19200/38400/57600/115200 |
| `relay.dev.delay` | 下拉 + 输入 | 写后延时 ms，常用 20/50/100/200 |
| `relay.dev.inverted` | 复选 | IO 低电平有效 |
| `relay.dev.polarity` | 复选 | 绑定/脉冲极性取反 |
| `relay.dev.enable` | 复选 | 启用设备 |
| `relay.dev.testChannel` | 下拉 | 测试通道 1..N |
| `relay.dev.status` | 只读文本 | 当前状态/错误 |
| `relay.dev.info` | 只读多行 | 最近动作回执 |

按钮：

- `relay.dev.new` 新增设备；
- `relay.dev.save` 保存设备（当前设备名覆盖，旧名可迁移）；
- `relay.dev.delete` 删除设备；
- `relay.dev.refresh` 刷新 COM 列表；
- `relay.dev.on` / `relay.dev.off` 测试吸合/释放；
- `relay.dev.pulse` 测试脉冲，时长取 `relay.dev.pulseHold`；
- `relay.dev.pulseHold` 下拉 + 输入（0.5/1/2/5 秒）。

行为：

- 保存写回 `relay_devices`，调用 `core_->set_service_config` 后 `config_save`，再 `mgr_->apply_config`。
- 测试前检查该 COM 是否被运行中的串口通道占用；占用时中文提示，不强行打开。
- 测试 ON/OFF 走 `relay_ctrl_set`；测试脉冲走 `relay_ctrl_run_mode` 或异步脉冲路径，不冻结 UI。
- 状态区显示 CH1..CHn 的 on/off、busy、last_error。

### 3.3 页 2：板卡绑定

顶部选择目标通道：

- `relay.bind.target`：下拉，列出所有 SSH/串口通道；这是“按钮属于哪块板子”的唯一入口。
- `relay.bind.list`：下拉，列出当前通道中 `backend=relay` 的按钮（显示 `id · label`）。
- `relay.bind.new`、`relay.bind.save`、`relay.bind.delete`、`relay.bind.test`。

编辑字段：

| 控件 | 说明 |
|---|---|
| `relay.bind.id` | 稳定 id，如 `power_on` |
| `relay.bind.label` | 显示在板卡按钮条上的文字 |
| `relay.bind.relay` | 继电器设备下拉 |
| `relay.bind.channel` | 继电器通道下拉 1..N |
| `relay.bind.mode` | hold_on / hold_off / pulse |
| `relay.bind.hold` | 脉冲/保持时长，下拉 + 输入 |
| `relay.bind.polarity` | 单按钮极性取反 |
| `relay.bind.enable` | 是否显示在按钮条 |

生成按钮（用户提到的“生成按钮”在此落地）：

- `relay.bind.generate`：按当前选中的继电器、目标和通道，一键生成/更新三个标准按钮：
  - `power_on`：`backend=relay`，`channel=1`，`mode=hold_on`；
  - `power_off`：`backend=relay`，`channel=1`，`mode=hold_off`；
  - `reboot`：`backend=relay`，`channel=2`（若设备只有 1 路则用 1 路），`mode=pulse`，`hold_seconds=1.0`。
- 生成时如果同 id 已存在，覆盖其 relay/channel/mode 字段，不静默新增重复 id。
- 生成后立即刷新 `relay.bind.list` 和主窗口按钮条。

预设快捷：

- `relay.bind.presetOn`、`relay.bind.presetOff`、`relay.bind.presetReboot` 只填充表单，不直接落盘；用户可改名后保存。
- `relay.bind.presetUpgradeMode` 切到“按钮脚本”页并生成“进升级模式”脚本按钮。

### 3.4 页 3：按钮脚本

顶部同样选择目标通道：

- `relay.script.target`：下拉。
- `relay.script.list`：下拉，列出当前通道 `backend=script` 或 `backend=commands` 的按钮。
- `relay.script.new`：新建草稿，默认 `button1 / 新按钮 / --lua + print('hello')`，可直接保存也可改名；不会出现“进升级模式”标题配登录脚本的错配。
- `relay.script.save`、`delete`、`test`。

字段：

| 控件 | 说明 |
|---|---|
| `relay.script.id` | 稳定 id |
| `relay.script.label` | 按钮文字 |
| `relay.script.kind` | 下拉：`Lua 脚本` / `板端命令` / `本机命令` |
| `relay.script.body` | 多行编辑：Lua 正文或命令列表（一行一条） |
| `relay.script.delay` | 命令间隔 ms，下拉 + 输入 |
| `relay.script.enable` | 是否显示在按钮条 |

映射：

- `Lua 脚本` → `backend=script`，`script=body`；
- `板端命令` → `backend=commands`，`run=channel`，`commands=body.splitlines()`；
- `本机命令` → `backend=commands`，`run=host`，`commands=body.splitlines()`。

预设：

- `relay.script.presetLogin`：Lua 调用 `channel.login()`；
- `relay.script.presetUboot`：发送回车，等待 `U-Boot` / `=>` 提示；
- `relay.script.presetUpgrade`：板端命令模板（`tftp` / `nfs` 相关命令留占位）；
- `relay.script.presetUpgradeMode`：生成“进升级模式”Lua 按钮，按当前绑定中的继电器名执行：
  - PWR off → MASKROM on → PWR on → MASKROM off，每步 `msleep` 留出建立时间。
- `relay.script.generateUpgrade`：把上述升级模式脚本生成/更新为当前通道的 `enter_upgrade_mode` 按钮。

### 3.5 按钮数据模型

所有按钮都挂在通道上，不建全局按钮表。配置结构：

```json
{
  "boards": [
    {
      "name": "ok3568",
      "serial_device": "COM5",
      "buttons": [
        {
          "id": "power_on", "label": "上电", "enable": true,
          "backend": "relay", "relay": "relay1", "channel": 1,
          "mode": "hold_on", "hold_seconds": 1.0,
          "polarity_inverted": false
        },
        {
          "id": "upgrade", "label": "升级", "enable": true,
          "backend": "commands", "run": "host",
          "commands": ["ping -n 2 127.0.0.1"], "delay_ms": 200
        },
        {
          "id": "enter_upgrade_mode", "label": "进升级模式", "enable": true,
          "backend": "script", "script": "--lua\n..."
        }
      ]
    }
  ],
  "ssh": [
    { "name": "demo1", "buttons": [ ... ] }
  ]
}
```

兼容读取 v2：

- `buttons[]` 是 canonical；
- 如遇 `relay_actions[]` / `actions[]`，分别映射成 `backend=relay` / `backend=commands` 追加到 `buttons`；
- `relays` 若是对象映射，按名称转为 `relay_devices[]`；
- 旧 `relay_devices` 数组继续支持。

`id` 在单个通道内唯一；保存时若 id 冲突，给中文错误并阻止保存。

## 4. 板卡按钮条与执行

### 4.1 显示

- 主窗口在终端上方放一条动态按钮条。
- 只显示当前通道 `enable=true` 的按钮；按配置顺序排列。
- 宽度不足时按钮只能换行/压缩；不允许压到终端或与搜索框重叠。设计上按钮条是独立一行，终端从按钮条下方开始。
- 每个真实按钮挂桥接 id：`board.btn.<按钮id>`；动作通过按钮条触发，与配置窗口“测试”走同一执行器。
- 当前通道无按钮时整条隐藏。

### 4.2 执行器

新增 `BoardActionRunner`：

- 输入：通道名、按钮配置、执行时的配置快照、目标 `IBridge*`。
- 输出：`{ok, message, output}`，通过 `PostMessage` 回 UI；配置窗口与主窗口各自接收。
- 执行在后台线程，不冻结 UI；同一时刻允许多个不同按钮并行，但同一继电器设备的脉冲串行化。
- 状态栏/消息区显示开始、成功、失败原因和耗时。

后端语义：

1. `backend=relay`
   - `hold_on` / `hold_off` / `pulse` 全部走 `relay_ctrl_run_mode`；
   - 执行前检查继电器串口是否被运行中的串口通道占用；
   - `pulse` 的 `hold_seconds` 默认 1.0，允许 0.05–30 秒。
2. `backend=commands`, `run=channel`
   - 逐条写入目标通道，每条后等待 `delay_ms`；
   - 串口按板卡 `line_ending` 配置发送；SSH PTY 固定只发 `\r`，避免 CR 与 LF 各提交一行、多出空提示符；
   - `channel.exec` 同样对 SSH 只发 `\r`；
   - 返回入队字节数，不等待命令输出。
3. `backend=commands`, `run=host`
   - 本机 `cmd.exe /c` 执行，捕获 stdout/stderr；
   - 每条命令独立进程，工作目录为工程根；
   - 超时 120 秒，超时杀进程树；
   - 输出截断到 64 KB，写入消息区并落 `output\board_action.log`。
4. `backend=script`
   - 走 Lua 5.4；首行 `--lua` 或 `#!lua` 可选（v3 默认按 Lua 执行，为兼容 v2 仍识别这两个标记）；
   - 兼容旧行式 DSL 仅在检测到无 `--lua` 且首行不是 Lua 语法时启用，优先保证 Lua。

### 4.3 Lua API

保留 v2 兼容 API，并扩展本机执行：

| API | 说明 |
|---|---|
| `channel.mark()` | 返回 `{epoch, seen}` 游标 |
| `channel.read_since(mark)` | 返回增量文本 |
| `channel.write(text)` | 原样写 |
| `channel.send(token)` | 发送单个按键 token（enter/up/down/tab/esc/ctrl-c 等） |
| `channel.keys(seq)` | 发送按键序列 |
| `channel.send_keys(seq, duration, interval)` | 循环发送，返回次数 |
| `channel.login()` | 用通道配置的用户名/密码登录 |
| `channel.wait_mark(mark, needle, timeout)` | 等到输出包含 needle，返回累计文本；超时返回 nil, "timeout" |
| `channel.wait_idle(mark, idle_ms, timeout)` | 等到输出空闲，返回累计文本 |
| `channel.exec(cmd, timeout)` | **v3 新增**：写命令 + 回车，等到空闲，返回输出文本 |
| `host.exec(cmd, timeout)` | **v3 新增**：本机执行命令，返回 `{ok, exit_code, output}` |
| `msleep(ms)` | 休眠，受 180 秒总时限约束 |
| `relay(name, ch, "on"|"off")` | 直接操作继电器设备 |
| `relay_mode(name, ch, mode, hold, polarity)` | **v3 新增**：hold_on/hold_off/pulse |
| `action(id)` | 同步执行同通道另一个按钮；允许 commands（含 host），禁止嵌套 script |
| `print(...)` | 写入消息区 |

沙箱：

- 不开放 `io`、`os`、`package`；
- 保留 `base/string/table/math/utf8`；
- 总墙钟 180 秒；Lua 指令钩子每 10k 条检查一次，纯循环也能中止；
- `host.exec` 单条 120 秒，`channel.exec` 默认 10 秒、可传 0–60 秒；
- 输出总量限制 1 MB，超出截断并标记。

## 8. 验收标准

### 8.1 逐控件

每个控件都必须真实操作一次，不能只读 `/state`：

1. 下拉：逐项切换，确认选中值保存后重启仍存在；
2. 输入：输入合法值、空值、超范围值，确认中文错误提示；
3. 复选：勾选/取消，确认保存与执行行为；
4. 按钮：点击后确认业务结果，不只确认 `ok:true`；
5. Tab：逐页切换，确认每页控件可见且不重叠；
6. 主窗口按钮条：点击每个板卡按钮，确认对应继电器/命令/Lua 真实执行；
7. 关闭/重开窗口：确认配置和服务状态不丢。

### 8.2 遮挡

- 枚举窗口内所有可见业务控件，取屏幕矩形两两求交；业务控件重叠面积必须为 0。
- 分组框、标题、消息区不算业务控件，但也不能覆盖按钮。
- 在 100%、125%、150% DPI 下各检查一次；最小窗口尺寸下再检查一次。
- 板卡按钮条、左侧选项卡、终端三者不能互相覆盖；窗口缩到最小时按钮条可换行/折叠，但终端必须有可见区域。
- 响应式：客户区 `<820 DIP` 时左侧通道管理器必须自动收起，`>=820 DIP` 自动恢复；`btn.toggleTree` 与 `Ctrl+B` 必须能手动双向切换；窄窗 480 DIP 宽时工具栏 6 个按钮与搜索框不得重叠。回归脚本 `tests/ui_responsive_check.ps1` 必须全绿。
- 删除通道：必须两次确认才落盘；删除当前通道后自动切到第一条剩余通道；删空最后一个通道后保留一个空画框，空画框提示必须为“没有通道，点‘新建’创建一条”，进程保持运行；新建通道后必须自动接回该空画框。回归脚本 `tests/ui_delete_channel_check.ps1` 必须全绿。

### 8.3 时延

- 串口回显：应用层 ≤ 100 µs（S11 基线 36 µs）；
- SSH 回显：常态 ≤ 100 ms，尖峰记录并说明；
- 继电器动作：从点击到状态回执 ≤ 500 ms（脉冲总时长除外）；
- Lua `host.exec`：记录进程启动到返回的墙钟，不把命令本身耗时算进 UI 延时；
- 所有动作必须显示耗时，便于用户判断。

### 8.4 功能回归

- S11 的 TFTP/共享/NFS 全部重跑；
- 主窗口断开后 COM 释放，重连可用；
- 配置保存后重启，继电器设备、按钮、服务配置均保持；
- 退出后 18086/18082/69/111/1058/2049 无监听。

## 9. 风险与决策

| 风险 | 决策 |
|---|---|
| 三个窗口同时打开、同一配置保存互相覆盖 | 每次保存以 `core_->config()` 当前值为基底，只改本窗口字段；保存后刷新其它窗口的只读状态 |
| 继电器 COM 与串口通道冲突 | 执行前检查运行中的串口通道，冲突时中文提示，不强行抢占 |
| Lua 脚本卡死 UI | 后台线程 + 180 秒墙钟 + 指令钩子；窗口关闭不等待脚本 |
| 本机命令输出过大 | 64 KB 截断，完整日志落 `output\board_action.log` |
| 板卡按钮过多挤占终端 | 按钮条独立一行，超出宽度时横向压缩；最小窗口下允许折叠为“更多” |
| Telnet/PowerShell 只有分类没有通道 | 分类显示 `(0)` 与说明；配置结构预留 `kind`，后续接入协议时不改左侧信息架构 |
| “生成按钮”语义不明确 | 明确定义为“生成标准继电器按钮”和“生成进升级模式按钮”，在对应页提供，不放在隐藏菜单 |
