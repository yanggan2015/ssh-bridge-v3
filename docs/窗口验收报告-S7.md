# SSH Bridge 3.0 · 窗口验收报告（S7 第一块：SFTP 文件传输）

- 日期：2026-11-21
- 分支：`main`（本次提交为 S7 第一块）
- 构建：`mingw32-make clean && mingw32-make -j4`，产物 `output/build/ssh_bridge3.exe`
- 真机：当前 Windows 主机（150% DPI），桥接 `http://127.0.0.1:18086`
- 测试通道（本机配置实际存在）：串口 `ztl=COM3@1500000`、`ok3568=COM5@115200`、两个 loop 通道 `loop1/s6loop2`；SSH `ssh-link-demo1 39.97.234.200:52222`、`ssh-link-demo2 sshbridge.online:52223`（demo/123456）

## 1. 本步交付范围

1. 独立 SFTP 会话（libssh，独立于终端 SSH 通道），不与终端抢占通道。
2. 非模态双栏面板：左本地、右远端；顶部 SSH 通道下拉 + 连接按钮。
3. 本地/远端路径均为**可编辑下拉**（路径必须允许自由输入，符合“能选就不输、必须输入时用可编辑下拉”的硬规则）；通道为只读下拉。
4. 目录刷新 / 上级 / 双击目录进入；本地目录、远端目录后缀区分（`\` 与 `/`）。
5. 上传 / 下载：64KB 分块、实时进度与百分比、队列状态、可取消。
6. 临时文件 `.part` + 成功后重命名；取消/失败清理临时文件，不留下半截目标文件。
7. MD5 校验：上传后对远端整文件计算 MD5 并与本地比对，回执“MD5 一致/不一致”；下载回执本地 MD5。
8. 桥接：`sftp.*` 共 20 个稳定 id，全部进入 `/ui-tree`，动作 `click/select/set_text` 可用；`/state.ui.sftp` 暴露目录项、选中项、传输阶段、进度、队列、状态原文。
9. 菜单「文件 → SFTP 文件传输…（F7）」；关闭主窗时自动关闭面板。

## 4. 延时实测（客户端含 HTTP 往返）

| 场景 | 实测 |
|---|---|
| 面板打开到 20 控件可枚举 | 688ms（含首连进行中） |
| 面板打开 → SSH 就绪 + 首目录 | 约 0.9–1.4s（SSH 握手为主） |
| 远端列目录刷新 | 288ms |
| 小文件下载（28B，含本地 MD5） | 333ms |
| 小文件上传（28B，含远端 MD5 比对） | < 1s |
| 10MB 上传 | 进度连续，约 0.5–0.6MB/s；结束回执 MD5 一致 |
| 传输中关闭面板 | 158ms |

说明：上传结束的 MD5 校验需要回读远端整文件，10MB 文件会额外增加一段读取时间；这是“可证明的一致性”换来的成本，后续可改为远端 `md5sum` 以进一步降延时。

## 5. 本步发现并修复的问题

1. **P0 上传必失败**：`sftp_open` 的 `accesstype` 参数要 POSIX `O_*`，原实现误传 `SSH_FXF_*`，服务端返回 `No such file`。改为 `O_WRONLY|O_CREAT|O_TRUNC` 后创建成功（独立最小程序与真机双向验证）。
2. **P1 进度一直 0%**：`total_` 只在传输结束后才写入，UI 与 `/state` 拿不到实时总大小。改为把 `total_` 直接传给传输层，进度条与百分比实时更新。
3. **P1 完成状态被目录刷新覆盖**：上传成功后自动刷新远端目录，把“上传完成 · MD5 一致”立刻改成“目录：/tmp · 6 项”。改为静默刷新，完成态保留到下一次用户动作。
4. **P2 连接/列目录时状态显示旧文案**：`status_text` 优先取 note。改为阶段 1/2 强制显示“正在连接…/正在读取目录…”。
5. **P2 控件重叠**：标签/路径、队列/状态各重叠数像素，重排坐标后归零。
6. **P2 队列行与状态行重复同一句**：队列行改为“阶段 · 队列 n”。
